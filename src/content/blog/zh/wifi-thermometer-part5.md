> 感知能力全齐了之后，电池产品面临真正的生死题：**功耗**。一直全速醒着跑，一节电池撑不过一个月；我们的目标是让它绝大部分时间在睡觉，10 秒醒一次干完活接着睡。
> 本篇是低功耗三部曲的第一篇：怎么睡、怎么醒、以及全系列最著名的坑——**睡醒之后，世界变了**。

---

## 一、本篇目标与效果

**目标**：单片机平时睡在 STOP 模式（电流降到微安级），按下按键才醒来干活（闪灯 + 串口问好），干完接着睡。顺手用万用表实测对比"醒着"和"睡着"的电流差。

**做完你会懂**：Cortex-M 的睡眠模式分级、STOP 和"假睡"的区别、唤醒源是怎么回事、以及为什么唤醒后必须重新配置时钟——这条是本篇的灵魂。

## 二、原理 10 分钟

### 2.1 睡眠模式分级：不是"睡"和"醒"两个状态

Cortex-M 系列给了一条功耗阶梯（名称是 ARM 通用术语，各芯片厂叫法会改）：

| 模式 | 内核时钟 | 外设/SRAM | 唤醒方式 | 电流量级 |
|------|---------|----------|---------|---------|
| Sleep（睡） | 停 | **外设全在跑** | 任何中断 | 降一半左右 |
| **Stop（深睡）** | 停 | 时钟全停，**SRAM 保留** | EXTI/RTC/低功耗定时器 | 几 µA~几十 µA |
| Standby（假死） | 停 | SRAM 丢失，只留备份域 | 复位脚/RTC | 1~2 µA |

看出区别了吗：**Stop 是"记住一切的睡"**——变量还在、程序计数器还在，醒来从睡着那行代码继续跑；Standby 是"失忆的睡"——SRAM 清空，醒来等于复位重来。

我们的产品选的是深睡（华大叫 Deepstop，对应 Stop 这一级）：**醒来能接着跑程序，这是事件驱动架构的前提**——下一篇的状态机就靠"睡醒从断点继续"活着。

为什么 Sleep 模式不够？它的电流还是毫安级，因为时钟树还在给外设输血。**省电的本质是给时钟"断粮"**：Stop 模式把主时钟发生器整个关掉，只留一个低功耗时钟源（32 kHz 晶振或内部低速 RC）给"闹钟"供电。

### 2.2 闹钟从哪来

STM32F103 没有产品那种 LPTIM（低功耗定时器），它的 STOP 唤醒闹钟是 RTC——这个配置比较繁琐，学习版我们用更直观的：**EXTI 外部中断唤醒**（按键）。产品版的定时唤醒原理在"原版对照"一节专门讲，数学很好玩。

### 2.3 进入 STOP：三行寄存器的事

```c
PWR->CR &= ~PWR_CR_PDDS;              // 1. 选 Stop（不是 Standby）
SCB->SCR |= SCB_SCR_SLEEPDEEP_Msk;    // 2. 告诉内核：这次是深睡
__WFI();                              // 3. Wait For Interrupt，睡着
/* …… 被唤醒后，从这里继续 …… */
```

唤醒源要提前配好：把按键脚配成 EXTI 下降沿中断，睡着后按下按键，EXTI 一拍，内核醒来，从 `__WFI()` 的下一行继续执行。

### 2.4 本篇灵魂：睡醒之后，时钟"降级"了

这是最反直觉、也最容易踩的坑，单独放大讲。

STOP 模式把主时钟发生器关了。唤醒的瞬间，硬件为了保证"立刻有得跑"，会自动把系统时钟切回**内部高速时钟 HSI（8 MHz）**——即使你睡前跑在 72 MHz。

后果是连锁的：

- 延时函数按 72 MHz 装的初值，实际 8 MHz 在跑 → **延时慢 9 倍**；
- UART 波特率寄存器按 72 MHz 算的 → 唤醒后实际波特率错乱，串口全是乱码；
- 凡是依赖 `SystemCoreClock` 的代码全部失真。

**正确姿势**：唤醒后第一件事，重新执行时钟配置（把 HSE+PLL 重新开起来，切回 72 MHz），并同步更新 `SystemCoreClock` 全局变量。

产品代码里这个操作被封装成固定动作：退出低功耗的函数里自动调用"时钟恢复"，不让应用层有机会忘记。你将在本篇亲手复现"忘记恢复"的故障——先感受疼，再记住药。

## 三、动手写代码

### 第一步：按键 EXTI 配置（PA0）

```c
static void wakeup_button_init(void)
{
    RCC->APB2ENR |= RCC_APB2ENR_IOPAEN | RCC_APB2ENR_AFIOEN;

    GPIOA->CRL &= ~(0xF << 0);          // PA0 浮空输入
    AFIO->EXTICR[0] &= ~(0xF << 0);     // EXTI0 源 = PA0
    EXTI->IMR  |= EXTI_IMR_MR0;         // 不屏蔽
    EXTI->FTSR |= EXTI_FTSR_TR0;        // 下降沿触发
    NVIC_EnableIRQ(EXTI0_IRQn);
}
```

### 第二步：进入 STOP + 唤醒后恢复时钟

把第 1 篇的 72 MHz 时钟配置抽成函数 `clock_config_72mhz()`，然后：

```c
static void enter_stop(void)
{
    uart_puts("going to sleep...\r\n");
    while ((USART1->SR & USART_SR_TC) == 0) { }   // 等最后一个字节发完！（第 2 篇彩蛋）

    EXTI->PR = EXTI_PR_PR0;            // 清一次挂起标志，防误唤醒

    PWR->CR |= PWR_CR_CRDS;            // 调压器低功耗（省一点是一点）
    PWR->CR &= ~PWR_CR_PDDS;
    SCB->SCR |= SCB_SCR_SLEEPDEEP_Msk;
    __WFI();                           // ★ 睡着。唤醒后从下一行继续 ★
    SCB->SCR &= ~SCB_SCR_SLEEPDEEP_Msk;

    /* —— 唤醒必做：时钟降级了，立刻恢复 —— */
    clock_config_72mhz();              // 重开 HSE+PLL 并切回 72MHz
    SystemCoreClock = 72000000;        // 同步更新全局时钟变量
}
```

### 第三步：主循环——睡-醒循环

```c
int main(void)
{
    clock_config_72mhz();
    SystemCoreClock = 72000000;
    uart_init();
    wakeup_button_init();

    uint32_t wake_count = 0;
    while (1) {
        wake_count++;
        uart_puts("awake! #");
        uart_put_num(wake_count);      // 简易整数打印，前面篇练习过
        uart_puts("\r\n");

        for (int i = 0; i < 3; i++) {  // 闪 3 下灯表示"我醒了"
            led_toggle();
            delay_ms(100);
        }

        enter_stop();                  // 睡。下次按键醒来wake_count还在！
    }
}
```

EXTI 中断函数可以空着——它的存在只是为了唤醒，不需要干活：

```c
void EXTI0_IRQHandler(void)
{
    EXTI->PR = EXTI_PR_PR0;            // 清挂起标志
}
```

**重点观察**：`wake_count` 在 STOP 后保持递增——SRAM 保住了，这就是 Stop 级深睡的价值。

### 第四步：电流实测（万用表登场）

把万用表调到 mA 档，**串进供电回路**（电池正极 → 万用表红表笔 → 板子 VCC）：

- 醒着（闪灯+发串口时）：几 mA ~ 二十几 mA；
- 睡着（STOP 中）：跌到几十 µA 甚至更低（蓝色药丸板载电源指示灯会吃掉一部分，别惊讶，扣掉它才是 MCU 真实水平）。

两个数量级以上的差距，就是低功耗产品的全部意义。

- [ ] 按一下按键：灯闪、`awake! #2`——**计数连续，SRAM 无损**；

## 五、原版对照（CIU32F003）：LPTIM 定时唤醒的数学

产品没有人按按键，它靠的是 **LPTIM1**（低功耗定时器），核心特征是：**主时钟全关它照样跑**，因为它吃的是独立的低速时钟 RCL 32 kHz。

10 秒定时怎么装？LPTIM 是 16 位计数器，最大数到 65535，32 kHz 直接数 10 秒要数到 327680，爆表了。所以先分频：

```
32768 Hz ÷ 8 = 4096 Hz        ← 预分频
4096 Hz × 10 s = 40960        ← 没超 65535，可行
```

于是自动重装载值 ARR = 40960 − 1，计数器从 0 数到 40959 正好 10 秒，数满触发唤醒，CPU 被叫醒。

产品的完整唤醒链：`LPTIM1（RCL 时钟）→ 数满 10 s → 唤醒 CPU → 第一件事恢复 48 MHz 时钟 → 采样上报 → 回 Deepstop`。整条链里电流账是这样的：10 秒周期里 ~50 ms 醒着干活（几 mA），~9.95 s 深睡（几 µA），平均下来只有几十 µA——电池就能按"年"计算寿命了。

产品还配了一个省电细节：进 Deepstop 前关掉 ADC 和带隙基准（BGR）这类耗电外设，醒来再开。睡觉前的关灯清单，第 6 篇讲看门狗时会一起汇总。

## 六、彩蛋：整机电流超标，凶手是一根 IO 线

产品整机电流测试不达标。代码翻了个底朝天：时钟降了、外设关了、Deepstop 进去了……还是高。

最后靠示波器 + 逐引脚排查找到真凶：**PA3**。

Wi-Fi 模组断电休眠后，它一侧的 IO 上残留着电平，通过 PA3 一路倒灌进 MCU。MCU 这边在 Deepstop，IO 默认状态没配对，就像睡着的人忘了关门，隔壁的电流悄悄渗进来。单看每个器件都"符合规格"，加起来就是电池杀手。

修复：进 Deepstop 前，把 PA3 配置成**模拟输入**（输入缓冲器关闭，物理上近似断开），顺手把全板没用的引脚全部配成模拟输入。改完，电流达标。

给你一份可以直接抄的"入睡前检查清单"，这是产品用真金白银换来的：

- [ ] 时钟恢复函数放在唤醒路径的**第一行**，不给任何人跳过它的机会；
- [ ] 串口等外设的最后一帧等 **TC** 发完再睡；
- [ ] ADC/BGR 等耗电外设关掉；
- [ ] 所有与外部器件相连的 IO，确认睡眠态电平不会倒灌（拿不准就配模拟输入）；
- [ ] 没用到的引脚一律模拟输入，不留浮空。

## 七、下篇预告

能睡能醒了，但还有个致命问题没解决：如果程序卡死在某个角落，单片机既不醒也报错，电池就这么被默默耗光。下一篇第 6 篇《睡梦里被狗咬醒怎么办》：独立看门狗 IWDG——一条只在断电时才会停止工作的狗，和"溢出周期必须大于睡眠周期"这条生死不等式。
