## 一、本篇目标与效果

**目标**：单片机通过串口和电脑对话——电脑发什么，它回什么（回显），并且每秒主动汇报一次"系统运行中，第 N 秒"。

**做完你会懂**：UART 帧长什么样、波特率到底在约定什么、中断为什么必不可少、环形缓冲区为什么是所有串口程序的标配。

## 二、原理 10 分钟

### 2.1 UART：两根线的对话协议

UART 只需要两根数据线：TX（我发你收）和 RX（你发我收），外加共地。它长盛不衰的原因就两个字：**简单**。一帧数据长这样：

```
空闲 ─┐                                            ┌─ 空闲
      │ 起始位 │ D0 │ D1 │ ... │ D7 │ 停止位 │
      └───────┴────┴────┴─────┴────┴───────┘
       1位低电平  8位数据，低位先发     1位高电平
```

约定只有两个：

- **波特率**：每秒传多少个"位"。9600 波特率 = 每秒 9600 位。一帧 10 位（起始+8 数据+停止），所以 **9600 波特率下传 1 字节约 1.04 毫秒**。后面涂鸦模组就用 9600，这个数字要记牢；
- **数据格式**：8 位数据、无校验、1 位停止位，缩写 **9600-8-N-1**。收发双方这两样必须一致，差一个就全是乱码。

为什么产品选 9600 这种"龟速"？因为对面是 Wi-Fi 模组，双方线长、干扰环境、电平匹配都一般，低波特率最稳；而且温湿度数据量小，9600 完全够用。**够用且稳，永远优先于快**——又是一次小资源产品的价值观。

### 2.2 波特率怎么写进寄存器

USART 有个波特率寄存器 BRR，公式是：

```
BRR = 时钟频率 / 波特率
```

8 MHz 时钟配 9600：`8000000 / 9600 ≈ 833`；72 MHz 时则是 `7500`。注意这个值**跟着时钟变**——上一篇刚学过"时钟是全局状态"，这里立刻用上。为简单起见，本篇我们在默认 8 MHz 下做实验。

### 2.3 轮询的局限：CPU 不能一直守着

先发后收的最朴素写法是轮询（polling）：

```c
// 发送：等发送数据寄存器空，再写入新字节
while ((USART1->SR & USART_SR_TXE) == 0) { }
USART1->DR = ch;

// 接收：等收到数据
while ((USART1->SR & USART_SR_RXNE) == 0) { }
ch = USART1->DR;
```

发送用轮询问题不大（反正得等它发完），但**接收用轮询就有大麻烦了**：对方字节什么时候来？不知道。你只能 `while` 死等——那主循环里其他事（点灯、采样）全停摆。

更糟的是：字节是一个一个来的，等你从死等中醒来处理完一个，下一个字节可能已经到了接收寄存器，再下一个直接**把没读走的字节覆盖掉**。9600 波特率下，1 毫秒覆盖一个，CPU 随便打个盹就丢数据。

### 2.4 RXNE 中断 + 环形缓冲区：标准答案

正确姿势：每收到一个字节，硬件触发一次**接收非空中断（RXNE）**，中断服务程序（ISR）里立刻把字节搬进一个缓冲区，然后马上退出。主循环什么时候有空，什么时候再来慢慢处理缓冲区里的数据。

中断里不做事、只搬运，缓冲区就是这个模式的灵魂。最常用的缓冲区结构是**环形缓冲区（ring buffer）**，一个定长数组加两个下标：

```
        tail（中断写）          head（主循环读）
          ↓                       ↓
  [ ][ ][a][b][c][d][ ][ ][ ][ ][ ]
          └──── 未读数据 ────┘
```

- 中断收到字节：`buf[tail] = data; tail = (tail + 1) % SIZE;`
- 主循环读取：`data = buf[head]; head = (head + 1) % SIZE;`
- 空判断：`head == tail`；满判断：`(tail + 1) % SIZE == head`（牺牲一个格子区分"满"和"空"）。

如果缓冲区大小取 2 的幂（16、32、64……），取模可以用按位与提速：`tail = (tail + 1) & (SIZE - 1)`。小资源产品的习惯，处处精打细算。

## 三、动手写代码

### 第一步：接线

```
CH340 模块          蓝色药丸
  RX      ◄────────  PA9  (USART1_TX)
  TX      ────────►  PA10 (USART1_RX)
  GND     ────────►  GND
```

注意：TX 接 RX、RX 接 TX，**交叉连接**，新手第一大翻车点。CH340 模块有 5V/3.3V 跳线，拨到 **3.3V**。

### 第二步：GPIO 与 USART 配置

PA9/PA10 是 USART1 的默认引脚，要配成**复用推挽输出**（ Alternate Function，引脚交给 USART 硬件管）：

```c
#include "stm32f103xb.h"
#include <stdint.h>

#define BUF_SIZE   64
#define BUF_MASK   (BUF_SIZE - 1)

static volatile uint8_t  s_buf[BUF_SIZE];
static volatile uint16_t s_head = 0;
static volatile uint16_t s_tail = 0;

static void uart_init(void)
{
    RCC->APB2ENR |= RCC_APB2ENR_USART1EN;      // 开 USART1 时钟
    RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;        // 开 GPIOA 时钟

    // PA9 = TX：复用推挽输出 50MHz → CNF=10, MODE=11
    GPIOA->CRH &= ~(0xF << 4);
    GPIOA->CRH |=  (0xB << 4);
    // PA10 = RX：浮空输入 → CNF=01, MODE=00
    GPIOA->CRH &= ~(0xF << 8);
    GPIOA->CRH |=  (0x4 << 8);

    USART1->BRR = 8000000 / 9600;              // 8MHz / 9600 ≈ 833

    USART1->CR1 = USART_CR1_TE                 // 使能发送
                | USART_CR1_RE                 // 使能接收
                | USART_CR1_RXNEIE             // 接收非空中断
                | USART_CR1_UE;                // USART 总开关（最后开）

    NVIC_EnableIRQ(USART1_IRQn);               // 在 NVIC 里放行 USART1 中断
}

static void uart_putc(char ch)
{
    while ((USART1->SR & USART_SR_TXE) == 0) { }  // 等发送寄存器空
    USART1->DR = ch;
}

static void uart_puts(const char *s)
{
    while (*s) uart_putc(*s++);
}

static int uart_getc(void)                        // 主循环用：取一个字节，无数据返回 -1
{
    if (s_head == s_tail) return -1;
    uint8_t d = s_buf[s_head];
    s_head = (s_head + 1) & BUF_MASK;
    return d;
}
```

中断服务函数（函数名必须和启动文件向量表里的一致）：

```c
void USART1_IRQHandler(void)
{
    if (USART1->SR & USART_SR_RXNE) {           // 确认是接收中断
        uint8_t d = (uint8_t)USART1->DR;        // 读 DR 会自动清 RXNE 标志
        uint16_t next = (s_tail + 1) & BUF_MASK;
        if (next != s_head) {                   // 缓冲区没满才存，满了丢弃
            s_buf[s_tail] = d;
            s_tail = next;
        }
    }
}
```

三个细节必须强调：

1. **ISR 里只搬数据不做业务**。在中断里跑 `uart_puts` 这种带循环的函数，轻则丢字节，重则系统瘫痪；
2. **读 DR 会清 RXNE 标志**，这是硬件约定，不用手动清；
3. `s_buf/s_head/s_tail` 加了 `volatile`——它们会被中断修改，不加的话编译器可能把主循环里的判断优化掉，程序就"明明收到了却看不见"。`volatile` 是中断共享变量的护身符。

### 第三步：主循环——回显 + 每秒心跳

```c
int main(void)
{
    uart_init();
    uart_puts("UART ready. Echo mode.\r\n");

    uint32_t seconds = 0;
    uint32_t ms_cnt  = 0;

    while (1) {
        /* 回显：缓冲区里有啥吐啥 */
        int ch = uart_getc();
        if (ch >= 0) uart_putc((char)ch);

        /* 大约 1 秒的心跳（延时函数照第 1 篇的 SysTick 版）*/
        delay_ms(10);
        ms_cnt += 10;
        if (ms_cnt >= 1000) {
            ms_cnt = 0;
            seconds++;
            char msg[32];
            int n = 0;
            const char *p = "alive, tick=";
            while (p[n]) { msg[n] = p[n]; n++; }
            msg[n++] = (char)('0' + (seconds % 10) + 0); // 简化：只放个位
            msg[n++] = '\r'; msg[n++] = '\n'; msg[n] = 0;
            uart_puts(msg);
        }
    }
}
```

## 四、烧录与验收

打开串口助手（SSCOM），选 CH340 对应的 COM 口，参数 **9600、8、N、1**，打开：

- [ ] 复位单片机后，助手收到 `UART ready. Echo mode.`；
- [ ] 在助手里敲字符发送，能收到一模一样的回显；
- [ ] 不敲键盘时，每秒收到一条 `alive, tick=...`；
- [ ] （进阶验证）把助手波特率改成 115200 再发——收到一串乱码。改回 9600 又正常。**乱码 = 波特率不一致**，把这个反射刻进肌肉记忆。

## 五、原版对照（CIU32F003）

产品的 UART 模块（对接涂鸦 Wi-Fi 模组）配置完全同构，只是封装进了 BSP 层：`bsp_uart.c` 里集中定义 UART 实例、引脚、**波特率宏（9600）**，初始化和本篇一样走"开时钟→配 GPIO→配波特率→开 RXNE 中断"。

两个值得一提的产品级差异：

1. **接收缓冲直接对接涂鸦 SDK**。产品的 RX 中断里没有自己存环形缓冲，而是每个字节直接喂给 SDK 的 `uart_receive_input()`，由 SDK 内部维护协议解析缓冲。第 9 篇移植 SDK 时我们会站到这个对接点上；
2. **发送缓冲 128 字节**。产品有一次性发"14 个 DP 合单帧"的需求（第 11 篇详解），发送缓冲不够会把帧截断。缓冲区多大不是拍脑袋，是被最大的那一帧决定的。

## 六、彩蛋：两个和"发送"有关的翻车现场

### 6.1 最后一字节没发完，程序就跑了

产品早期有个诡异现象：发给 Wi-Fi 模组的帧**偶尔少最后一个字节**，校验和对不上，模组拒收。概率不高，很难复现。

凶手是 `TXE` 和 `TC` 两个标志的区别：

- `TXE`（发送数据寄存器空）：你把字节交给了 USART，它还在移位寄存器里排队往线上送——**这时候 TXE 已经置位了**；
- `TC`（发送完成）：移位寄存器也空了，最后一位真的送上了线。

当时的"发完等待"等的是 TXE。大部分时候没事，但主循环一旦在发完最后一字节后立刻干别的（比如进低功耗睡眠、关掉 USART），那个还在路上的字节就被掐死在线上。等改成等 `TC`，故障绝迹。

这条经验写进了团队 checklist：**"发送完毕"要等 TC，不是 TXE。** 尤其在低功耗产品里——发完就睡，睡得太急会吃掉帧尾。

### 6.2 串口助手的"隐形地板"

另一个初学高频坑：串口助手显示收到了数据，但程序里 `uart_getc()` 就是取不到——最后发现是**中断没进**，而中断没进是因为 `NVIC_EnableIRQ` 之前 USART 已经在收数据，溢出标志（ORE）先置位卡住了状态。处理接收错误标志（ORE/FE/PE）也是中断服务函数的职责之一，真实项目的 ISR 开头通常有一行"清错误标志"的防御代码。

教训：**示例代码省掉的防御，就是产品事故的种子。** 学习阶段可以把错误处理简化，但心里要清楚它省在哪。
