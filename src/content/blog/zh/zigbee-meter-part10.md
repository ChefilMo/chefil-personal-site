## 一、为什么是段码屏？

电表的"脸"有几个候选：LED 数码管（便宜但功耗高、数字少）、点阵 OLED（信息量大但贵、烧屏、怕高温）、段码 LCD（功耗微安级、阳光下清晰、成本低、工业表计标配）。配电箱里的电表常年通电，但显示并不需要一直变化——段码屏"静态显示几乎不耗电"的特性完美匹配。

代价是：段码屏没有通用驱动 IC 的标准协议，每块屏的段码表都是定制化的——SEG（段）和 COM（公共端）怎么交叉、哪个段对应显存哪个位，全看屏厂图纸。**写段码屏驱动 = 写一本"引脚到像素"的对照字典**，这是本篇最硬核的部分。

## 二、VK1621：HT1621 兼容的段码驱动 IC

VK1621 是兼容 Holtek HT1621 的段码 LCD 驱动芯片：支持 1/2、1/3 bias，2/3/4 COM，内置 RC 振荡器和蜂鸣器/看门狗/时基（我们全不用）。它管 32×4 = 128 个段码位，我们的屏只用 17 个 SEG × 4 COM。

硬件连接还是 GPIO 模拟（TLSR8258 引脚紧张是老生常谈了）：

| VK1621 引脚 | MCU 引脚 | 作用 |
|-------------|----------|------|
| CS | PC2 | 片选，低电平有效 |
| WR | PC3 | 写时钟（每 bit 拉低拉高一次） |
| DATA | PD2 | 数据线 |

三线写时序（`WriteClockVk1621`）：

```c
void WriteClockVk1621(void)
{
    VK1621_WR_L();
    delay_nus(VK1621_CLK);      /* 每边 10us → 时钟约 50kHz */
    VK1621_WR_H();
    delay_nus(VK1621_CLK);
}
```

50kHz 很慢，但段码屏的刷新需求也极低（人眼看不出 100ms 的刷新延迟），慢时钟换来 GPIO 时序的宽松余量，划算的取舍。

### 2.1 两种帧：命令帧与显存帧

VK1621（HT1621 协议）线上跑着两种帧，起始码区分：

**命令帧**（`WriteCommandVk1621`）：起始码 `100` + 8 位命令 + 1 个 don't-care 位。初始化命令序列（`Vk1621_Init`）：

```c
/* 初始化命令序列 */
OSC_ON      0x01    /* 开 RC 振荡器 */
DISP_ON     0x03    /* 开 LCD 偏压输出 */
COM_1_3__4  0x29    /* 1/3 bias, 4 COM ← 本屏配置 */
BUZZ_OFF    0x08    /* 关蜂鸣器 */
IRQ_DIS     0x80    /* 关 IRQ */
TIMER_DIS   0x04    /* 关时基 */
WDT_DIS     0x05    /* 关看门狗 */
```

关掉所有用不到的外设是嵌入式礼仪——每多一个运行的功能都是功耗和干扰源。

**显存帧**（`WritenDataVk1621`）：起始码 `101` + 6 位起始地址 + N×4 位数据（每个 SEG 4 bit，对应 4 个 COM），地址自动递增：

```
CS 拉低
  → 送 101（3 bit 起始码）
  → 送 6 位地址（A5..A0，MSB 先行）
  → 送数据：每个 SEG 的 4 bit（bit0→COM0, bit1→COM1, ...）
  → 地址自动 +1，连续送 N 个 SEG
CS 拉高
```

## 三、段码映射：驱动里最烧脑的字典

### 3.1 显存模型

VK1621 内部是 32×4 bit 的显存 RAM，我们的 buffer 对应其中 17 字节：

```c
UCHAR vk1621_dispram[17];   /* 每个字节的低 4 位有效：bit0→COM0, bit1→COM1, bit2→COM2, bit3→COM3 */
```

这块屏的怪癖是：**一个"8 字"（七段数码管）横跨两个 SEG**。例如第一个数字：

```
SEG0 的 4 bit：COM1=1D, COM2=1E, COM3=1F    （三个段）
SEG0 的 bit0(COM0)：1A
SEG1 的低 3 bit：1B, 1C, 1G                  （三个段）
SEG1 的 bit3(COM3)：留作图标位！
```

七段被拆成"3+1+3"放在相邻两个字节里，而且奇数字节的最高位被图标占用——**写一个字 = 操作两个字节、避开图标位**。

### 3.2 字模表与拆分写入

字模按 A/B/C/D/E/F/G 七位编码，高 4 位是 SEG 偶字节的段，低 4 位是 SEG 奇字节的段。显示一个数字的拆分技巧（`disp_3num`）：

```c
dat8 = dat/100%10;                            /* 取百位 */
vk1621_dispram[0]  = shuzi_zimo[dat8] >> 4;           /* 高 3 段 → 偶数 SEG（整体覆盖） */
vk1621_dispram[1] &= 0xf1;                            /* 清段但保留 bit0 和 bit3 图标位 */
vk1621_dispram[1] |= shuzi_zimo[dat8] & 0x0E;         /* 低 3 段 → 奇数 SEG */
```

注意第二个操作的位运算设计：`&= 0xf1` 保留 bit0（图标）和 bit3（另一个图标/保留位），清掉 bit1-2（旧数字段），`|= & 0x0E` 只写 bit1-3 中的段位……具体哪些位是段、哪些是图标，完全由这块屏的图纸决定。**这段代码就是"图纸的代码化"**——换一块屏，字模表、`&` 掩码、`>>4` 拆分全部要重画。

前导零消隐：值 <100 时百位清 0，<10 时十位清 0——段码屏的经典需求，"  5"比"005"可读得多。

### 3.3 一个真实的 bug：全局数组与硬件 RAM 的脱节

项目实际的修复记录里有一个非常"段码屏"的 bug，值得完整复盘：

**症状**：设备断网后，LCD 上的 WiFi 图标（P3）不消失——明明离线了还显示在线。

**排查**：`disp_4num` 里 P3 的逻辑是这样的：

```c
/* 只在"在线"时点亮，离线时没有显式清除 */
if (is_online) {
    vk1621_dispram[10] |= 0x01;    /* P3 在 dispram[10] 的 bit0 */
}
/* 没有 else 分支！离线时不清 */
```

看起来离线时 dispram[10] 保持旧值（1），图标该亮着——但别忘了每次 `disp_4num` 开头有个 `Vk1621_DisAll(0x00)` 全清！清完之后 dispram 全 0，图标应该灭掉啊？

问题就出在 **`Vk1621_DisAll(0x00)` 清的是 LCD 硬件的 RAM，不是 `vk1621_dispram[]` 这个全局数组**：

```c
void Vk1621_DisAll(UCHAR flag)
{
    /* 直接操作硬件显存：全部地址刷成 flag */
    WritenDataVk1621(0, buf_all_flag, VK1621_SEGNUM);
    /* 注意：没有同步修改 vk1621_dispram[]！ */
}
```

于是形成"双份状态"：硬件 RAM 是全 0，但软件数组里 `dispram[10].bit0` 还是 1。而 `WritenDataVk1621` 写的是软件数组——下一次刷新时，数组里的旧 P3 值又被写回硬件，图标复活。

**根因：硬件状态与软件镜像之间的同步缺失**。修复：离线分支补上 `vk1621_dispram[10] &= ~0x01;`（同时更彻底的做法是让 `Vk1621_DisAll` 也清零软件数组）。

**教训：凡是"软件镜像 + 硬件状态"的双层结构，写操作必须两边同步**——这在 LCD、LED 移位寄存器、IO 扩展芯片驱动里是通病。

## 四、disp_4num：产品的主显示函数

`disp_4num(up, down, is_online, up_down, abc)` 是上层唯一调用的显示接口，五个参数撑起整个 UI：

| 参数 | 含义 |
|------|------|
| `up` / `down` | 上行/下行 4 位数字（内部已转定点） |
| `is_online` | 是否在线（控制 WiFi 图标 P3） |
| `up_down` | 1=显示 V/A 单位图标，0=显示 kWh/W 单位图标 |
| `abc` | 相位指示：1=A, 2=B, 3=C（点亮 P4/P5/P6 之一） |

内部布局：

```c
/* 上行 4 位数字：dispram[0..7]（4 个"8 字"各跨 2 SEG） */
/* 下行 4 位数字：dispram[9..16] */
/* 单位图标行：dispram[8] */
/* 小数点：P1=dispram[5].bit0, P2=dispram[14].bit0 */
/* 在线图标：P3=dispram[10].bit0 */
/* 相位图标：P4/P5/P6 = dispram[9/11/13].bit3（abc 参数选通） */
```

大数自动降级：值 ≥1000 时自动 ÷10 并点亮对应小数点——4 位数码管显示 12345 的折中方案是显示 "1234.5"。这个"自动规格化"让上层不用关心量程切换。

最后 `WritenDataVk1621(0, vk1621_dispram, 17)` 一口气把 17 字节刷进硬件——段码屏的刷新就是一次完整的显存传输，没有"只改一位"的局部更新（改了哪一位都得全刷，反正 17×4=68 bit 也就 1.4ms）。

## 五、六页轮显与全笔画测试

### 5.1 页面调度

计量读取模块定义了 6 个页面：

| 页 | 上行 | 下行 | 相位标 |
|----|------|------|--------|
| A_V_I | 电压 (V×10) | A 相电流 (mA÷100=A×10) | A |
| A_E_P | A 相电量 (正+反, kWh×10) | A 相功率 (\|W×10\|) | A |
| B/C 各两页 | 同上 | | B/C |

刷新入口 `app_lcd_refresh()` 做的事很纯粹：按当前页从 `METER_DATA_T` 取数 → 各字段除以各自的比例因子统一成 "×10" 格式 → 调 `disp_4num`。比例换算关系：

```c
/*   voltage : V×10   → 直接传 (div=1)
     current : mA     → A×10  (div=100)
     power   : W×10   → 直接传 (div=1)
     energy  : kWh×100→ kWh×10 (div=10)  */
```

翻页入口 `app_lcd_page_next()`：`sg_lcd_page++` 到 LCD_PAGE_MAX 回卷到 0，然后刷新。注意它先检查"是否在全笔画模式"——是的话先退出全笔画再翻页（交互逻辑：三击后的短按 = "退出测试，顺便翻页"）。

### 5.2 全笔画测试模式

三击按键触发的产线测试（`app_lcd_all_segments_on`）：

```c
VOID_T app_lcd_all_segments_on(VOID_T)
{
    sg_lcd_all_segments_mode = TRUE;
    Vk1621_DisAll(0x0F);        /* 所有 SEG 的所有 COM 点亮 → 全笔画 */
    tal_sw_timer_stop(sg_etimer_lcd_all_segments);
    tal_sw_timer_start(sg_etimer_lcd_all_segments, LCD_ALL_SEGMENTS_TIMEOUT_MS, TAL_TIMER_ONCE);  /* 5s 自动退出 */
}
```

设计意图：出厂检验时工人三击按键，屏幕全亮——肉眼检查有没有断笔、缺段，5 秒自动恢复正常显示。期间 `app_lcd_refresh` 直接 return（不刷屏），退出时恢复当前页面数据。

这个模式还呼应了第 08 篇的恢复出厂：`app_meter_read_factory_reset` 里强制退出全笔画（`sg_lcd_all_segments_mode = FALSE`），防止"恢复出厂后屏幕还在测试模式"的怪状态。

### 5.3 离线显示策略

第 04 篇讲过：断网时 LCD 照常刷新（`POWER_ON_LEAVE` / `JOIN_TIMEOUT` / `NWK_LOST` 等都重启周期定时器），只有 WiFi 图标熄灭。这是后续两个修复的成果，判断依据就是 `app_nwk_is_online()` 全局标志——数据模型、网络状态机、显示层三者的联动点。

## 六、NTC 测温：341 点查表 + 二分查找

电表要测环境温度（过热保护、精度补偿的输入）。传感器是 NTC 热敏电阻（负温度系数：温度↑ 电阻↓）接在 PB6 与 3.3V 之间，10kΩ 上拉分压。

### 6.1 硬件链路

```
3.3V ── 10kΩ 上拉 ──┬── PB6 (ADC ch6)
                    │
                  NTC ── GND
```

ADC 读电压 → 分压公式反推 NTC 电阻 → 查表 → 温度。每一步都有工程细节。

### 6.2 ADC 采样

```c
#define ADC_SAMPLE_AVG_CNT  4

INT32_T app_adc_read_pb6(VOID_T)
{
    INT32_T sum = 0;
    for (int i = 0; i < ADC_SAMPLE_AVG_CNT; i++) {
        sum += tkl_adc_read(...);      /* 12 位，3.3V 参考 */
    }
    return sum / ADC_SAMPLE_AVG_CNT;   /* 4 次平均压噪声 */
}
```

4 次平均是最朴素的滤波——NTC 信号慢变化，多次平均不吃亏。供电噪声大的场景可以上 8 次或中值滤波。

### 6.3 电阻换算与边界处理

```c
/* ADC(mV) → NTC 电阻(kΩ) */
FLOAT_T __adc_to_ntc_resistance(INT32_T adc_val)
{
    if (adc_val <= 0)    return NTCTAB[0] + 1;        /* 对地短路：返回"极低温"值 */
    if (adc_val >= 3300) return NTCTAB[340] - 0.001f; /* 开路(满量程)：返回"极高温"值 */
    return PULLUP_RESISTANCE_K * adc_val / (3300 - adc_val);   /* R = 10k × ADC/(3300-ADC) */
}
```

边界设计很有意思：**不返回错误码，而是返回"超出物理可能"的电阻值**——短路返回比 -40℃ 还大的电阻，开路返回比 300℃ 还小的电阻，让后续查表自然落在表的两端，再被 `NTC_TEMP_MIN/MAX`（-40/300℃）截断。用"哨兵值"代替错误传播，代码更顺。

### 6.4 查表 + 线性插值

NTC 的阻温关系是指数曲线（Steinhart-Hart 方程），浮点计算太奢侈。工程标准解法：**预生成阻值表 + 二分查找 + 线性插值**。

```c
/* NTCTAB[341]：-40℃ ～ 300℃ 每 1℃ 一个阻值，降序排列（温度升 → 阻值降） */
STATIC CONST FLOAT_T NTCTAB[341] = { 191.21f /* -40℃ */, ..., 0.15f /* 300℃ */ };

/* 二分查找阻值所在的温度区间 */
STATIC INT32_T __ntc_find_index(FLOAT_T r)
{
    INT32_T low = 0, high = 340;
    while (low < high) {
        INT32_T mid = (low + high) / 2;
        if (r > NTCTAB[mid]) high = mid;      /* 阻值大 → 温度低 → 往左 */
        else               low  = mid + 1;
    }
    return low;
}

/* 查表 + 线性插值，输出 0.1℃ 精度 */
FLOAT_T app_adc_get_temperature(INT32_T adc_val)
{
    FLOAT_T r = __adc_to_ntc_resistance(adc_val);
    INT32_T idx = __ntc_find_index(r);
    /* temp = idx 基准温度 + (区间阻值差比例) × 1℃ */
    FLOAT_T temp = -40 + idx + (NTCTAB[idx] - r) / (NTCTAB[idx] - NTCTAB[idx+1]);
    if (temp < -40)  temp = -40;
    if (temp > 300)  temp = 300;
    return temp;
}
```

341 点降序表，二分查找 9 次比较定位区间，一次线性插值得到 0.1℃ 精度——整个测温链路（ADC 采样 + 换算 + 查表）耗时不到 1ms，浮点运算总共就几次除法。查表法是资源受限系统的经典权衡：用 341×4=1364 字节 Flash 换零复杂运算。

### 6.5 开路检测的语义

第 08 章见过这一行：

```c
if (adc_val >= 3200) {
    meter->temp_current = 0;    /* NTC 探头没接：报 0℃ 而非 300℃ */
}
```

为什么开路报 0 不报最大温？因为"探头没接"是产线和安装现场的常见状态（NTC 是选配），显示 0℃ 是明确的"无效"信号（电表内部不可能 0℃），而 300℃ 是"着火了"的误报。语义设计：**无效值要选一个"不可能被误认为真实"的数**。

## 七、踩坑实录

**坑 1：段码表和实际屏不符。**
症状：显示数字缺段、错位。原因：换屏厂没更新字模表。对策：先跑 `Vk1621_Test()`（全亮→全灭→逐点扫描）确认 SEG/COM 映射，再对字模。

**坑 2：WiFi 图标离线不消失。**
前文详解：软件数组与硬件 RAM 双份状态失同步。

**坑 3：NTC 读数跳变。**
ADC 参考电压被 Wi-Fi/ Zigbee 发射拉低（共享 3.3V）。对策：4 次平均（代码已有）；更狠的方案是发射间隙采样，但电表场景没必要。

**坑 4：大数值溢出显示。**
电量超过 999.9 kWh 时 4 位管放不下。`disp_4num` 的 ≥1000 自动 ÷10 机制解决了数值层，但产品定义上"电量页最大显示 9999 kWh"要在物模型里注明（超了看 App）。

## 八、验证方法

1. **显示完整性**：三击全笔画，肉眼检查每个段；`Vk1621_Test` 逐点扫描定位坏段；
2. **六页数据**：短按翻页，每页数据与 App 对照（电压 ×0.1V、电流 ×0.001A、功率 ×0.1W）；
3. **断网显示**：断网关后 LCD 继续刷新、WiFi 图标熄灭，恢复后图标点亮；
4. **温度精度**：NTC 接标准电阻箱（或冰水混合物 0℃、沸水 100℃ 粗校），误差 ±1℃ 内；
5. **开路检测**：拔掉 NTC，温度应显示 0.0℃。

## 九、小结

- VK1621 三线 GPIO 时序（CS/WR/DATA），命令帧 `100` 起始、显存帧 `101` 起始，显存每个 SEG 4 bit 对应 4 COM；
- 段码驱动的核心是"SEG-COM-像素"字典：字模拆分、图标位掩码全部来自屏图纸；
- 软件镜像与硬件状态必须同步更新（WiFi 图标 bug）；
- 六页轮显 + 全笔画测试 + 断网续显，构成电表的人机交互闭环；
- NTC 测温 = 分压反推电阻 + 341 点二分查表 + 线性插值，哨兵值处理开路短路。

设备能看、能按、能测温了。下一篇讲让数据"可信"的机制：校准体系、功率报警与继电器保护——也就是这个电表作为"保护装置"的价值所在。
