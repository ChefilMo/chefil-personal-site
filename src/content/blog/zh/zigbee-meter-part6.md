> 目标：用 GPIO 模拟 SPI 驱动 HLW8112，读懂 A/B 两相的电压、电流、功率、电量，并处理一个硬件留下的"交叉映射"伏笔

## 一、HLW8112 是什么？

HLW8112 是合力为（Holtek 系国产计量芯片）推出的一颗**双通道电能计量芯片**：内置两路独立的 ADC（电流 A/B 通道 + 一路电压通道），能同时计量两个回路的电流、一个有功功率、电量、功率因数、频率、相角。我们的 A、B 两相就靠它一颗搞定。

它和第 07 篇的 HLW8110（单通道、UART 接口）是姊妹型号，寄存器布局完全一致（同一套地址表），区别只在通信接口：**8112 走 SPI，8110 走 UART**。这个系列的设计很讨巧——学会一颗，第二颗只看驱动差异即可。

先看它能给我们什么（寄存器地址表，两芯片共用）：

| 寄存器 | 地址 | 字节数 | 内容 |
|--------|------|--------|------|
| SYSCON | 0x00 | 2 | 系统配置：通道使能、PGA 增益 |
| EMUCON | 0x01 | 2 | 计量控制：能量累加、脉冲输出 |
| EMUCON2 | 0x13 | 2 | 计量控制 2：数据更新率、读后清零 |
| RMS_IA / RMS_IB | 0x24 / 0x25 | 3 | A/B 通道电流有效值 |
| RMS_U | 0x26 | 3 | 电压有效值 |
| POWER_PA / POWER_PB | 0x2C / 0x2D | 4 | A/B 通道有功功率 |
| ENERGY_PA / ENERGY_PB | 0x28 / 0x29 | 3 | A/B 通道电能脉冲计数 |
| PF | 0x27 | 3 | 功率因数 |
| UFREQ | 0x23 | 2 | 电压频率 |
| ANGLE | 0x22 | 2 | 电流电压相角 |
| RMS_IAC…ENERGY_BC | 0x70–0x77 | 2×8 | **出厂校准系数** |
| CHECKSUM | 0x6F | 2 | 系数区校验和 |

计量芯片的哲学是：**它不做浮点运算，只给你定点原始值**。电压有效值寄存器就是一个 24 位整数，要变成"220.5V"，必须乘上出厂校准系数再做定点换算——这套公式是 datasheet 给的，但理解它才能调对它。

## 二、GPIO 模拟 SPI：四个引脚的手摇时序

TLSR8258 有硬件 SPI，但引脚资源紧张（本项目 SPI 引脚 PD7/PD3/PD4/PC1 同时还要给 LCD、UART 让路），所以驱动用**纯 GPIO 位操作**模拟 SPI 模式 0（CPOL=0，上升沿采样）：

```c
/* 写一个字节，MSB 先行 */
STATIC VOID_T HLW8112_SPI_WriteByte(UINT8_T x)
{
    for (UINT8_T i = 0; i < 8; i++) {
        if (x & (0x80 >> i))  HLW8112_SDI_H;  else HLW8112_SDI_L;   /* 数据先就位 */
        HLW8112_SCLK_H;
        delay_hlw(HLW_SPI_SPEED);               /* 32 个空循环 ≈ 几 us */
        HLW8112_SCLK_L;
        delay_hlw(HLW_SPI_SPEED);
    }
}
```

```c
/* 读一个字节 */
STATIC UINT8_T HLW8112_SPI_ReadByte(VOID_T)
{
    UINT8_T u8_data = 0;
    for (UINT8_T i = 0; i < 8; i++) {
        u8_data <<= 1;
        HLW8112_SCLK_H;
        delay_hlw(HLW_SPI_SPEED);
        if (IO_HLW8112_SDO_H) u8_data |= 0x01;   /* 时钟高电平期间采样 */
        HLW8112_SCLK_L;
        delay_hlw(HLW_SPI_SPEED);
    }
    return u8_data;
}
```

时序要点：

- **MSB 先行**：计量芯片的寄存器都是高位在前，与 UART/I2C 习惯一致；
- **模式 0**：时钟空闲低电平，数据在上升沿（SCLK 拉高期间）被对端采样；我们的发送方在拉**高之前**把数据位放好，接收方在**高电平期间**采样 MISO；
- **速度**：`HLW_SPI_SPEED=32` 个空循环约几微秒一位，一个字节约 50us，读 3 字节寄存器 + 命令 ≈ 200us——同步阻塞可接受（这是和第 07 篇 UART 方案的关键分歧点）。

一次完整读寄存器（`Read_HLW8112_RegData`）：

```
CS 拉低
  → 写命令字节（寄存器地址，bit7=0 表示读）
  → 连续读 N 字节（高位在前填入 union）
CS 拉高
```

写寄存器则命令字节 bit7 置 1（`addr | 0x80`），后跟 N 字节数据。**SPI 帧没有校验和**——可靠性靠"写完读回验证"（`Check_WriteReg_Success` 读回 SYSCON/EMUCON/EMUCON2 比对）和 8112 特有的 RDATA 镜像校验（后面讲）。

GPIO 引脚映射：SDI（主出从入）=PD7、SCLK=PD3、SDO（主入从出）=PD4、CS=PC1。注意 8112 的 SDO 是开漏输出，初始化时要把 SDO 对应的 MCU 引脚设为输入。

## 三、初始化：三个寄存器定终身

`Init_HLW8112()` 的完整流程：

```
1. GPIO 初始化（PD4 输入，PD7/PD3/PC1 输出，CS 拉高）
2. 写使能：SPI 帧发 EA E5（关闭写保护）
3. 通道选择：EA 5A（指定用 A 通道做 PF/相角/视在功率计算）
4. SYSCON ← 0x0F04     ← 系统配置
5. EMUCON ← 0x1003     ← 计量控制
6. EMUCON2 ← 0x03FF    ← 更新率 + 读后不清零
7. IE ← 0x0000         ← 关所有中断
8. 写禁止：EA DC
9. 读 0x70-0x77 校准系数并做 CheckSum 校验
10. Set_V_Zero()       ← 电压过零检测（INT1 输出）
11. Set_underVoltage() ← 欠压 180V 阈值（INT2 输出）
12. Read_HLW8112_State() 读回全部状态寄存器
```

三个核心寄存器的逐位含义：

**SYSCON ← 0x0F04**：

```
0F 04 = 0000 1111 0000 0100
         ││││ ││││
         ││││ └┴┴┴── 电压 PGA = 1 倍增益（bit2-0 = 100 → PGA=1）
         ││└┴─────── B 通道电流 PGA = 16 倍增益（bit5-4 = 11）
         └┴──────── A 通道电流 PGA = 16 倍增益（bit7-6 = 11）

高字节 0x0F = 同时使能 A、B 两路 ADC
```

PGA（可编程增益放大器）的选择是计量电路设计的一环：电流采样用锰铜分流器或 CT，信号幅值小，需要 16 倍增益放大到 ADC 满量程附近以获得最佳精度；电压采样经大电阻分压后信号已经不弱，PGA=1 防饱和。

**EMUCON ← 0x1003**：

```
高字节 0x10：比较器关闭（计量模式和漏电检测模式互斥）
低字节 0x03：使能 A 通道 + B 通道的有功电能累加
```

**EMUCON2 ← 0x03FF**——这一位改变了整个驱动架构：

```
bit0-1 (11) = 数据更新率 3.4Hz（每 294ms 刷新一次测量结果）
bit3   (1)  = 打开功率因数检测
bit8   (1)  = ZxEn 电压过零使能
bit9   (1)  = WaveEn 波形输出使能
bit10  (1)  = ★ EPA_CB：电量寄存器读后不清零
```

**`EPA_CB=1` 是本项目的基石配置**。HLW8112 的电量寄存器默认行为是"读一次就清零"——那每次读到的都是"两次读之间的增量"，掉电必丢、还难拼接。置位后电量自由累加（配合软件层的 NV 偏移机制，第 08 篇实现掉电续算）。

写保护的开关命令（EA E5 / EA DC）是个老式安全设计：防止程序跑飞时的随机 SPI 噪声改写校准系数。所以初始化流程是"开门 → 配置 → 关门"。

## 四、原始值 → 物理量：四条公式

系数校验通过后，8 个 16 位系数存入全局变量（`U16_RMSIAC/IBC/UC`、`U16_PowerPAC/PBC/SC`、`U16_EnergyAC/BC`）。换算全部在 `Read_HLW8112_*` 系列函数里，以 A 通道电流为例：

### 4.1 电流（A）

```c
F_AC_I_1 = (FLOAT_T)U32_RMSIA_RegData * U16_RMSIAC / 0x800000 / 0.2 / 1000 * D_CAL_A_I;
```

逐步拆解：

| 因子 | 含义 |
|------|------|
| `RMSIA` | 24 位 ADC 有效值原始计数 |
| `RMSIAC` | 出厂系数：1A 电流对应的理论计数比例 |
| `/ 0x800000` (2²³) | 定点归一化（Q23 格式） |
| `/ 0.2` | K1：与电流采样电阻/互感器变比相关的硬件常数 |
| `/ 1000` | 单位换算（公式给出的是 mA，我们要 A） |
| `× D_CAL_A_I` | 应用层校准系数（默认 1.0，校准篇调整） |

**bit23 陷阱**：若 `RMSIA` 的 bit23（0x800000）置位，结果视为无效（超量程标志），驱动直接清零电流值。

### 4.2 电压（V）

```c
F_AC_V = (FLOAT_T)U32_RMSU_RegData * U16_RMSUC / 0x400000 / 1 / 100 * D_CAL_U;
```

注意分母是 **2²² = 0x400000** 而不是 2²³——电压和电流的归一化位数不同，抄公式时最容易错的一位。

### 4.3 有功功率（W）——带方向的量

```c
if (U32_POWERPA_RegData > 0x80000000) {
    mag = ~U32_POWERPA_RegData;        /* 负功率：按位取反得幅值 */
} else {
    mag = U32_POWERPA_RegData;
}
F_AC_P_1 = (FLOAT_T)mag * U16_PowerPAC / 0x80000000 / 0.2 / 1 * D_CAL_A_P;
```

功率寄存器是 32 位有符号定点：**大于 0x80000000 表示反向功率**（电流方向与电压参考方向相反，即"发电"状态）。取幅值用按位取反（补码的模），符号单独记录。这个符号位就是正/反向电量分流的依据。

### 4.4 电量（kWh）

```c
F_AC_E_1 = (FLOAT_T)U32_ENERGYA_RegData * U16_EnergyAC / 0x20000000 / 0.2 / 1 * D_CAL_A_E;
```

分母 0x20000000 = 2²⁹ × 4096：2²⁹ 是定点归一化，4096 是 HFCONST 寄存器默认值（0x1000，脉冲常数）的合并简化。结果是 **0.001 kWh 每计数**——所以 DP 上报的电量要 ×100 才是 scale=2 的格式。

### 4.5 频率、功率因数、相角

```c
/* 频率：内置 3.579545MHz 晶振分频 */
F_AC_FREQ = 3579545.0f / (8 * U16_UFREQ_RegData);

/* 功率因数：Q23 补码定点 */
if (PF_RegData > 0x800000) PF = (0x1000000 - PF_RegData) / 0x7FFFFF;  /* 容性 */
else                       PF = PF_RegData / 0x7FFFFF;                /* 感性 */
```

PF 有个工程细节：功率小于 1W 时 PF 寄存器是噪声，强制清 0——不然空载时 App 上会看到 0.03 这样的"幽灵功率因数"。

## 五、电量防错读：RDATA 镜像交叉验证

8112 的电量读取有个教科书级的可靠性设计（`Read_HLW8112_EA/EB`）：

```c
/* 同时读 ENERGY_PA(0x28) 和 RDATA(0x44) */
Read_HLW8112_RegData(0x28, ...);   /* 主寄存器 */
Read_HLW8112_RegData(0x44, ...);   /* RDATA：上一个被读寄存器的镜像 */

/* 两者相等且不是 0x000000/0xFFFFFF 才采纳 */
if (energy_val == rdata_val && energy_val != 0x000000 && energy_val != 0xFFFFFF) {
    /* 有效 */
}
```

原理：HLW8112 内部会把**最近一次被读的寄存器值**镜像到 RDATA。连续读 ENERGY_PA 和 RDATA，如果 SPI 通信出现帧错位（时钟毛刺导致读写不同步），两个值就会不一致；0x000000 和 0xFFFFFF 则是通信中断时的典型"总线 stuck"值。三个条件叠加，把错读电量的概率压到接近零。

**正/反向电量分流**靠功率符号位（第 4.3 节）：当前功率为负，这次读到的电量增量计入反向累计；为正则计入正向。注意这是**增量判断**——读的是累计寄存器，两次读差值归属由当前功率方向决定。

## 六、物理通道 ≠ 逻辑相：交叉映射的伏笔

现在讲本项目最富戏剧性的一段。硬件布线时，HLW8112 的两个物理通道接端子没按"通道 A 接 A 相"的顺序：

| HLW8112 物理通道 | 实际接线端子 | 对应相位 |
|------------------|--------------|----------|
| 通道 A | 端子 1 | **B 相** |
| 通道 B | 端子 2 | **A 相** |

如果软件不做处理，App 上会出现"A 相电流显示的是 B 相的线"这种魔幻 bug。修正点在 `HLW8112_Measure()` 的聚合写入：

```c
/* 相位交叉映射：物理 B 通道 → 逻辑 A 相，物理 A 通道 → 逻辑 B 相 */
sg_meter_data->current_a = HLW_DBG_CURR(F_AC_I_2);   /* I_2 是物理 B 通道 */
sg_meter_data->current_b = HLW_DBG_CURR(F_AC_I_1);   /* I_1 是物理 A 通道 */
sg_meter_data->power_a   = HLW_DBG_PWR(F_AC_P_2);
sg_meter_data->power_b   = HLW_DBG_PWR(F_AC_P_1);

/* 功率因数：A 相 PF 用物理 B 通道的 P/(V×I) 计算，
   B 相 PF 直接用物理 A 通道的 PF 寄存器（PF 寄存器只在选定通道上有效） */
```

而**电量按端子记**（不按相）：`forward_energy_1` 记端子 1（B 相）的正向电量，`forward_energy_2` 记端子 2（A 相）的。这正是物模型里同时存在"按端子"（DP 56-61）和"按相"（DP 125-130）两套电量的原因——端子维度是物理事实，相位维度是用户视角，映射在聚合层（数据聚合函数，第 08 篇）完成。

这个交叉映射在后来的一次修复中才修正过来——此前 A/B 相的端子电量是反的。教训：**硬件原理图和驱动代码的通道定义必须有一张对照表**，不能假设"名字一样就是一回事"。

## 七、同步采集：HLW8112_Measure 的完整时序

一次采集（`app_meter_read_trigger_with_cb` 调用）的完整流程：

```
HLW8112_Measure()
  ├─ Read_HLW8112_PA_I()   读 0x24   → F_AC_I_1（物理 A 通道电流）
  ├─ Read_HLW8112_PB_I()   读 0x25   → F_AC_I_2
  ├─ Read_HLW8112_U()      读 0x26   → F_AC_V
  ├─ Read_HLW8112_PA()     读 0x2C   → F_AC_P_1
  ├─ Read_HLW8112_PB()     读 0x2D   → F_AC_P_2
  ├─ Read_HLW8112_EA()     读 0x28+0x44 交叉验证 → 正/反向电量增量
  ├─ Read_HLW8112_EB()     读 0x29+0x44
  ├─ Read_HLW8112_PFA/PFB() 读 0x27 / 计算 → F_AC_PF_1/2
  ├─ Read_HLW8112_Linefreq() 读 0x23 → F_AC_FREQ
  └─ 写入 METER_DATA_T（交叉映射 + 死区 + 钳位）
```

同步阻塞的合理性：全程约 20 次 SPI 事务 × 200us ≈ 4ms，在 10 秒周期的采集任务里完全可以接受。**同步是 8112 与 8110 的关键差异——8110 的 UART 方案用了异步状态机，第 07 篇会解释为什么同样的思路到 UART 就行不通。**

## 八、踩坑实录

**坑 1：GPIO 模拟 SPI 的 SDO 方向。**
8112 的 SDO 是开漏，MCU 侧必须配置为输入。如果配成输出，读操作会总线冲突，读到全 0 或全 1。

**坑 2：系数校验和不通过就初始化失败。**
`Judge_CheckSum_HLW8112_Calfactor` 验证 `~(0xFFFF + Σ8系数) & 0xFFFF == CHECKSUM(0x6F)`。失败说明通信或芯片异常，此时所有换算结果不可信。驱动里健康检查（第 08 篇）会对它做 3 次重试。

**坑 3：电量读后清零模式忘关。**
EMUCON2 的 EPA_CB 位（0x03FF 里已置位）如果没设，每次读 ENERGY 寄存器后芯片清零——表现为"电量每次都是从 0 开始的小数字"。排查时先读 EMUCON2 确认。

**坑 4：PGA 配置与硬件不匹配。**
换采样电阻后增益没变，表现为小电流时读数全零、大电流时饱和。SYSCON 的 PGA 位要和硬件分压/分流参数一起核算。

## 九、验证方法

1. 上电后串口应出现 `Judge_CheckSum_HLW8112_Calfactor OK`（系数校验通过）；
2. 接已知负载（如 100W 灯泡），对比 `F_AC_P_1/P_2` 与理论值，误差应在 ±2% 内；
3. 用校准源或标准表对比电压读数；
4. 长时间运行（24h）观察电量累计是否连续无跳变（RDATA 交叉验证的实战检验）。

## 十、小结

- HLW8112 双通道计量 = 寄存器读原始值 × 出厂系数定点换算，SPI 用 GPIO 位操作模拟模式 0；
- 初始化三寄存器定终身：SYSCON（通道+PGA）、EMUCON（累加使能）、EMUCON2（更新率 + **读后不清零**）；
- 换算公式注意 2²³/2²²/2²⁹ 的分母差异和功率符号位（正/反向）；
- RDATA 镜像交叉验证是低成本高可靠的防错读设计；
- 物理通道与逻辑相位的交叉映射要在驱动层显式处理。

A、B 两相的数据到手了。但三相还缺一相——而 C 相的 HLW8110 走的是 UART，还和我们唯一的调试串口抢地盘。下一篇是全系列技术密度最高的一篇：UART 通信、异步状态机、环形缓冲、以及一场持续 14 小时的"功率冻结"悬案。
