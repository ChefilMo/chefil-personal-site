> 前两篇装了"嘴"（UART）和"温湿度感觉"（I2C）。本篇补齐最后两种感知：**电池电压**（产品得知道自己还剩多少电）和 **NTC 外部温度**（那根可以插到室外的探头）。
> 它们背后是同一个模拟电路套路：**电阻分压 + ADC**。这个套路贯穿几乎所有电池供电产品，学会了就永久属于你了。

---

## 一、本篇目标与效果

**目标**：

1. 用两个电阻搭分压电路，测一个"模拟电池"的电压，串口打印出来；
2. 接上 NTC 热敏电阻，用手捏住探头，串口上的温度值肉眼可见地往上涨。

**做完你会懂**：ADC 在量什么、分压电路怎么设计、NTC 的阻值怎么变成温度，以及一个产品级技巧——**分压电路平时断电，测量时才通电**。

## 二、原理 10 分钟

### 2.1 ADC：把电压翻译成数字

ADC（模数转换器）回答一个问题：**这个引脚上的电压是 3.3V 的几分之几？**

STM32F103 的 ADC 是 12 位，意思是输出一个 0~4095 的数：

```
原始值 raw = (V_pin / V_ref) × 4095
```

参考电压 V_ref 就是 3.3V，所以**每个数字代表约 0.806 mV**。反过来：

```
V_pin = raw × 3.3 / 4095
```

这就是一切 ADC 应用的基石式公式。记住它，后面全是套娃。

### 2.2 分压：电压太高了怎么办

问题来了：电池电压可能高于 3.3V（比如两节新电池串联能到 3.3V 以上），ADC 引脚不能直接接电池。办法是中学生物……不对，中学物理：**电阻分压**。

```
 电池+ ──┬── R上 ──┬── R下 ──┬── 电池-
          │         │         │
         (高)     ADC引脚    GND
```

ADC 引脚测到的是中间点的电压：

```
V_adc = V_bat × R下 / (R上 + R下)
```

产品里就是这套：上电阻 270K 接电池，下电阻 3M 接地，分压比约 0.92。程序里用**反推公式**还原真实电压：

```
V_bat = V_adc × (R上 + R下) / R下
```

注意所有电阻值都定义成宏。**阻值是会换的**（不同批次 BOM 可能调整），写死在公式里就是给自己埋雷。

### 2.3 NTC：电阻怎么变成温度

NTC（负温度系数热敏电阻）：温度越高，电阻越小。我们买的 10K NTC 意思是 **25℃ 时阻值 10KΩ**，B 值 3950。

它也要接分压电路才能测——用 NTC 和一个精密电阻串联：

```
 3.3V ──┬── NTC ──┬── 10K(固定) ──┬── GND
         │         │               │
        (高)     ADC引脚          (低)
```

先由 ADC 电压反推 NTC 阻值：

```
R_ntc = R_fixed × (3.3 / V_adc − 1)
```

再由阻值算温度，datasheet 给的是 B 值公式：

```
T = 1 / ( 1/298.15 + (1/3950) × ln(R_ntc / 10000) )   单位：开尔文
℃ = T − 273.15
```

带 `ln` 的公式在电脑上没问题，但产品里跑 `logf()` 又慢又占 Flash。**产品的实际做法是一张 128 点查表 + 线性插值**：预先把 raw 值到温度的对应关系算好存进 Flash（const 数组，不占 RAM），运行时查表加一次比例换算，几微秒搞定。本篇先用公式版，第 18 篇盘点资源时你会看到表版的价值。

### 2.4 产品级技巧：测量才通电

分压电路有个隐形成本：**只要电池接着，分压电阻就在持续耗电**（3.3V / 3.27MΩ ≈ 1µA，看着小，乘上 24 小时乘上电池容量就得算账）。

产品的解法非常巧妙：**分压电路的下端不直接接地，而是接在一个 GPIO 上**。平时这个 GPIO 输出低电平……不，更绝的接法是：分压电路串在电池和一个 GPIO 之间，**平时 GPIO 输出低电平把电路整个短掉不通电，要测量时 GPIO 切输入（高阻）或输出高，电路才通电**。测完立刻断电。

产品里 NTC 走线就是"PA7 使能 → PA6 采集"，电池走线"PB1 使能 → PB0 采集"。一秒通电采几个点，其余时间零电流。本篇学习版简化处理（常通电），但要知道产品里这个省电手法真实存在。

## 三、动手写代码

### 第一步：接线（两路）

**模拟电池**（学习版用 USB 的 5V 当"待测高压"）：

```
USB 5V ── 100K ──┬── 100K ── GND
                 │
                PA0 (ADC_IN0)
```

分压比 1/2，5V → PA0 约 2.5V，安全。

**NTC**：

```
3.3V ── NTC ──┬── 10K ── GND
              │
             PA1 (ADC_IN1)
```

注意方向：**NTC 在上，固定电阻在下**——为什么强调方向，彩蛋见。

### 第二步：ADC 配置与读取（裸寄存器版）

```c
#include "stm32f103xb.h"
#include <math.h>

static void adc_init(void)
{
    RCC->APB2ENR |= RCC_APB2ENR_ADC1EN | RCC_APB2ENR_IOPAEN;

    GPIOA->CRL &= ~((0xF << 0) | (0xF << 4));   // PA0/PA1 模拟输入 CNF=00 MODE=00

    ADC1->SMPR2 |= (0x7 << 0) | (0x7 << 3);     // 通道0/1 采样时间 239.5 周期
                                                // （高内阻源要慢采样，NTC 分压阻抗高，必须慢）

    ADC1->CR2 |= ADC_CR2_ADON;                  // 上电
    ADC1->CR2 |= ADC_CR2_CAL;                   // 启动自校准
    while (ADC1->CR2 & ADC_CR2_CAL) { }         // 等校准完成（别跳过，首次读数会漂）
}

static uint16_t adc_read(uint8_t channel)       // channel: 0=PA0 1=PA1
{
    ADC1->SQR3 = channel;                       // 规则组第 1 个转换 = 该通道
    ADC1->CR2 |= ADC_CR2_SWSTART;               // 软件触发开始转换
    while ((ADC1->SR & ADC_SR_EOC) == 0) { }    // 等转换完成
    return (uint16_t)ADC1->DR;                  // 读 DR 自动清 EOC 标志
}
```

细节提醒：**读 DR 会清 EOC 标志**，这是硬件约定。记住它——第 0 篇彩蛋里"调试器 Live Watch 毁掉 ADC"的事故，机理就是调试器替你读了 DR、清了标志，程序在这里死等。

### 第三步：两个测量函数

```c
#define DIV_R_UPPER_KOHM   100.0f     // 分压上电阻（kΩ）
#define DIV_R_LOWER_KOHM   100.0f     // 分压下电阻
#define NTC_R_FIXED_OHM    10000.0f   // NTC 分压固定电阻
#define NTC_B_VALUE        3950.0f
#define NTC_R25_OHM        10000.0f

/* 模拟电池电压，单位 mV */
static uint32_t read_vbat_mv(void)
{
    uint16_t raw = adc_read(0);
    float v_adc = raw * 3300.0f / 4095.0f;
    return (uint32_t)(v_adc * (DIV_R_UPPER_KOHM + DIV_R_LOWER_KOHM)
                            / DIV_R_LOWER_KOHM);
}

/* NTC 温度，单位 0.1℃ */
static int16_t read_ntc_temp_x10(void)
{
    uint16_t raw = adc_read(1);
    if (raw < 2 || raw > 4093) return -999;     // 开路/短路保护（伏笔，见下文）

    float v_adc  = raw * 3.3f / 4095.0f;
    float r_ntc  = NTC_R_FIXED_OHM * (3.3f / v_adc - 1.0f);

    float t_k = 1.0f / (1.0f / 298.15f + (1.0f / NTC_B_VALUE)
                        * logf(r_ntc / NTC_R25_OHM));
    return (int16_t)((t_k - 273.15f) * 10.0f);
}
```

主循环每 2 秒各读一次，串口打印：

```
vbat=4968mV  ntc=25.4C
vbat=4968mV  ntc=26.1C   ← 手指捏住 NTC，温度上升
```

手指是 NTC 实验的官方指定加热器，免费、恒温 33℃ 左右、可重复使用。

## 四、烧录与验收

- [ ] 打印的 `vbat` 在 4900~5000 mV 之间（USB 5V 经分压再还原，有 1%~2% 电阻误差很正常）；
- [ ] 室温下 `ntc` 读数合理（20~30℃ 量级，和手头的温度计对比偏差 2℃ 内算优秀）；
- [ ] 捏住 NTC 10 秒，读数升到 30℃+；松手回落——**注意它反应慢，这是热敏电阻的物理特性，不是 bug**；
- [ ] （排障演练）把 NTC 两根线对调（NTC 和固定电阻互换位置），会发现温度读数变成了反逻辑：越加热读数越低。记住这个现象，彩蛋马上讲。

## 五、原版对照（CIU32F003）

产品的 ADC 模块和本篇同构，产品化的三个升级：

1. **使能脚省电**：如前述，NTC 分压由 PA7 使能、电池分压由 PB1 使能，测量流程是"使能 → 延时几 ms 等电压稳定 → 连采 N 次取平均 → 关闭使能"；
2. **查表代替公式**：128 点 raw→温度 的 const 表 + 线性插值，运行时零浮点；
3. **电量百分比分段线性映射**：电压百分比不是线性的（电池放电曲线中段陡两端平），产品用分段线性把电压折成 0~100% 电量，LCD 上低于 20% 亮低电图标。

另外产品上电采集的第一批数据会丢弃——ADC 刚通电时读数有建立过程，前几个样本是废的。这也是"连采取平均"之外的隐藏动机。

## 六、彩蛋：接反的分压

真实开发中，NTC 最初焊出来的方向和计算代码假设的方向**正好相反**——物理上 NTC 被放在了下臂、固定电阻放到了上臂。

这个错误在联调时很好抓：对着探头吹热风，串口温度一路**往下**掉；放冰箱里，温度往上蹿。方向全反。fix 就一行：把反推公式里的 `3.3/V_adc − 1` 换成 `V_adc/(3.3−V_adc)`（或者更治本：把电阻换回来）。

这个故事的教训不在公式，而在**联调时永远准备一个"已知真值"对照物**：手指头（33℃）、冰水混合物（0℃）、一杯开水（冒气即 100℃ 附近）。传感器读数和真值方向都不对的时候，先怀疑硬件接法，再怀疑代码。

还有一条产品级的后话值得现在记下：那个 `raw < 2 || raw > 4093` 的开路保护，在量产 9 天之后真的救了一次场——有用户把 NTC 探头拔了，ADC 读到开路假值，换算出 **-55℃**。这个值不仅误触发低温告警，更糟的是它超出了云端协议给外部温度规定的合法范围，导致**整帧数据被云端拒收，其他所有数据点一起陪葬**。后来固件升级为：raw 越界即判定"探头脱落"，显示 0、不上报、不参与告警。第 17 篇产测会再见到它。
