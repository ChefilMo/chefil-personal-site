> 上一篇我们装好了环境、让 Keil 认出了芯片。本篇开始写第一行代码：让板载 LED 闪起来。
> 听起来简单？点灯的代码确实只要十几行，但本篇要讲清楚三件事：**芯片从上电到执行 main() 之间发生了什么、时钟为什么决定一切、以及这个产品的"栈 1KB、堆 0 字节"是怎么回事**。

---

## 一、本篇目标与效果

**目标**：让蓝色药丸上的板载 LED（PC13）以 1 秒亮、1 秒灭的频率闪烁。

**做完你会懂**：复位向量与栈指针、RCC 时钟门控、GPIO 工作模式、SysTick 延时、启动文件里那两个决定内存命运的数字。

## 二、原理 10 分钟

### 2.1 从上电到 main()，芯片偷偷干了三件事

你写的 `main()` 并不是程序的第一行。芯片复位后，硬件会按死规定执行三步：

1. **从 Flash 地址 0x00000000 读出栈顶地址**，塞进 SP 寄存器（栈指针）；
2. **从地址 0x00000004 读出复位处理函数地址**，跳过去执行；
3. 复位函数（在启动文件 `startup_stm32f103xb.s` 里）做初始化：拷贝数据、清零 BSS，最后调用你熟悉的 `main()`。

注意第一步：**栈顶地址是"存在程序开头"的**。这引出一个重要事实——**栈的大小是在启动文件里写死的**，看一眼你工程里的启动文件：

```asm
Stack_Size      EQU     0x00000400      ; 1 KB
Heap_Size       EQU     0x00000200      ; 512 B
```

`EQU` 就是汇编里的"定义常量"。记住这两个数，本篇结尾我们回来算账。

### 2.2 时钟：单片机的心跳，还能换挡

STM32F103 上电后默认用内部高速时钟 HSI（8 MHz）。想跑得更快，要切换时钟源：外部晶振 HSE（8 MHz）经过 PLL 倍频到 72 MHz。关系像这样：

```
HSI 8MHz ──┐
           ├─→ SYSCLK（系统时钟）──→ 分频 ──→ 内核/HCLK/外设时钟
HSE 8MHz ──┘
              └── PLL ×9 ──→ 72MHz
```

我们的 CIU32F003 产品也是同样思路：上电默认 RCH/6 = 8 MHz，初始化时切到 RCH 48 MHz。

**为什么产品非要 48 MHz？** 因为后面要软件模拟 I2C、要跑协议栈，8 MHz 有点力不从心；但也没必要上 100 MHz——功耗和成本都会涨。小资源产品的时钟选型，永远是"够用就好"的精打细算。

本篇我们先在 8 MHz 下点灯，然后把时钟切到 72 MHz 再点一次——**你会亲眼看到延时变慢了 9 倍**，由此理解"SysTick 延时和时钟绑死"这条铁律。

### 2.3 GPIO：不是"接上线就能用"

PC13 接 LED，要让这个引脚输出高低电平，得先回答三个问题：

**问题一：这个引脚的时钟开了吗？**

STM32 的外设时钟默认全关（省电设计）。用 GPIOC 之前，必须先开它的时钟门：

```c
RCC->APB2ENR |= RCC_APB2ENR_IOPCEN;   // 使能 GPIOC 时钟
```

`RCC->APB2ENR` 是一个 32 位寄存器，第 4 位是 GPIOC 的开关。`|=` 把这一位置 1，其余位不动——寄存器操作的祖传手法。

**问题二：引脚配成什么模式？**

每个 GPIO 引脚有两个 4 位控制位（共 8 种模式）。我们要的是**推挽输出**（Push-Pull Output）：能主动输出高电平也能主动拉低，驱动 LED 绰绰有余。PC13 属于 GPIOC 的高 8 位，配置落在 `CRH` 寄存器：

```c
GPIOC->CRH &= ~(0xF << 20);   // 先清掉 PC13 的 4 个控制位
GPIOC->CRH |=  (0x2 << 20);   // CNF=00(推挽) MODE=10(2MHz输出)
```

**问题三：怎么改变引脚电平？**

两个选择：`ODR`（输出数据寄存器，读写整个端口）和 `BSRR`（位设置/清除寄存器，只写）。**永远优先用 BSRR**——它是原子操作，置 1 就置 1、清 0 就清 0，不会和其他位的操作打架：

```c
GPIOC->BSRR = GPIO_BSRR_BS13;   // PC13 = 1（置位）
GPIOC->BSRR = GPIO_BSRR_BR13;   // PC13 = 0（复位）
```

### 2.4 SysTick：内核自带的闹钟

延时怎么实现？STM32 内核里自带一个 24 位递减计数器 SysTick：装一个初值，它每个时钟周期减 1，减到 0 会置一个标志位。装 8000、时钟 8 MHz，就是 1 毫秒：

```c
SysTick->LOAD = 8000 - 1;        // 8000 个 8MHz 周期 = 1ms
SysTick->VAL  = 0;               // 清当前值
SysTick->CTRL = SysTick_CTRL_CLKSOURCE_Msk | SysTick_CTRL_ENABLE_Msk;
while ((SysTick->CTRL & SysTick_CTRL_COUNTFLAG_Msk) == 0) { }
```

**重点**：LOAD 里装多少，完全取决于当前时钟频率。时钟从 8 MHz 换成 72 MHz，同样的 8000 只对应 1/9 毫秒——这就是前面预告的"延时变慢 9 倍"的原理。

## 三、动手写代码

### 第一版：8 MHz，点亮

`main.c`：

```c
#include "stm32f103xb.h"

static void delay_ms(uint32_t ms)
{
    SysTick->LOAD = 8000 - 1;                    // 8MHz: 8000 拍 = 1ms
    for (uint32_t i = 0; i < ms; i++) {
        SysTick->VAL  = 0;
        SysTick->CTRL = SysTick_CTRL_CLKSOURCE_Msk
                      | SysTick_CTRL_ENABLE_Msk;
        while ((SysTick->CTRL & SysTick_CTRL_COUNTFLAG_Msk) == 0) { }
        SysTick->CTRL = 0;
    }
}

int main(void)
{
    RCC->APB2ENR |= RCC_APB2ENR_IOPCEN;          // 开 GPIOC 时钟

    GPIOC->CRH &= ~(0xF << 20);                  // PC13 推挽输出 2MHz
    GPIOC->CRH |=  (0x2 << 20);

    while (1) {
        GPIOC->BSRR = GPIO_BSRR_BS13;            // 亮（蓝色药丸 LED 低电平点亮，
        delay_ms(500);                           //  所以这里亮灭可能反着，正常）
        GPIOC->BSRR = GPIO_BSRR_BR13;            // 灭
        delay_ms(500);
    }
}
```

编译、下载（ST-Link 按上一篇配好的方式），观察现象。

**一个预告中的"坑"**：蓝色药丸的板载 LED 是低电平点亮的。如果你的灯"反着闪"（BS13 时灭），不是代码错了，是硬件接法如此——用万用表量一下 PC13 对地电压就明白了。嵌入式里，**代码的"对错"经常要和原理图对照着看**。

### 第二版：把时钟切到 72 MHz

在 `main()` 开头加：

```c
RCC->CR |= RCC_CR_HSEON;                        // 1. 开外部晶振
while ((RCC->CR & RCC_CR_HSERDY) == 0) { }      // 2. 等它稳定

FLASH->ACR |= FLASH_ACR_LATENCY_2;              // 3. Flash 加等待周期
                                                //    (72MHz 时 Flash 跟不上，要先说好)

RCC->CFGR |= RCC_CFGR_PLLSRC |                  // 4. PLL 源选 HSE
             (7 << RCC_CFGR_PLLMULL_Pos);       //    8MHz × 9 = 72MHz
RCC->CR |= RCC_CR_PLLON;                        // 5. 开 PLL
while ((RCC->CR & RCC_CR_PLLRDY) == 0) { }      // 6. 等 PLL 稳定

RCC->CFGR |= RCC_CFGR_SW_PLL;                   // 7. 系统时钟切到 PLL
while ((RCC->CFGR & RCC_CFGR_SWS_PLL) == 0) { } // 8. 确认切换成功
```

**注意了**：延时函数里那个 `8000` 还写着呢！现在时钟 72 MHz，8000 拍只有约 0.11 ms，LED 会以肉眼难辨的频率狂闪（看起来就是常亮微暗）。

把 `8000` 改成 `72000`，闪灯恢复正常。

**这个小事故是本篇最重要的教学点**：时钟配置是全局状态，SysTick、UART 波特率、定时器全都依赖它。真实项目里它散在多个文件里管理——这正好引出下面的彩蛋。

## 五、原版对照（CIU32F003）

产品代码走的是华大标准库（`std_` 前缀 API，风格类似 STM32 HAL/LL），时钟配置长这样：

```c
std_rcc_rch_config(STD_RCC_RCH_FREQ_48M);   // RCH 切 48MHz
std_delay_init();                           // 必须在时钟配好之后调用延时初始化
```

两个值得记的差异：

1. CIU32F003 的延时函数 `std_delayms()` 基于 SysTick，但内部依赖一个全局变量记录当前主频——**所以必须先配好时钟再调 `std_delay_init()`**，顺序反了延时就全错；
2. 它的启动文件里 `Stack_Mem EQU 0x400`（1 KB）、`Heap_Size EQU 0x0`（堆 0 字节）——产品把堆直接砍了，为什么？下一节彩蛋见。

## 六、彩蛋：堆 0 字节与"两个时钟宏"陷阱

### 6.1 为什么产品的堆是 0 字节？

栈和堆是 RAM 的两大用途。栈管函数调用和局部变量，由编译器自动算账；堆管 `malloc`，由程序员自己算账。产品 SRAM 总共 3 KB，看完成品的 `.map` 文件：栈 1 KB，剩下的全局变量、协议缓冲区一摆，**根本没有余量给堆**。

那干脆 `Heap_Size EQU 0x0`——让链接器在有人调用 malloc 时直接报链接错误，**把内存超支扼杀在编译期，而不是留到运行时莫名其妙死机**。

对新手的小建议：学习阶段堆可以先留着（默认 512 B 不妨事），但心里要有这根弦——每写一个全局大数组，就去 `.map` 文件的 `Image component sizes` 段看一眼 RW/ZI 涨了多少。这习惯从第一天养成，比以后熬夜找内存溢出强一万倍。

### 6.2 一个时钟，两处定义

真实项目里踩过一个很"嵌入式"的坑：CIU32F003 的时钟频率宏**在标准库配置头和 CMSIS 的 `system_xxx.c` 里各定义了一份**（`RCH_VALUE` 之类）。改时钟的人只改了一处，结果：

- 代码里实际跑在 48 MHz；
- 但协议栈和延时函数按 8 MHz 算时间。

现象非常魔幻：串口波特率全错、延时集体变慢 6 倍、看门狗周期不对。排查到最后，就是两个文件里的同一个数字不一致。

教训写成一句话：**凡是"同一个事实有两处来源"，迟早出事。** 要么合并成一处，要么改的时候用搜索确认所有引用点。这个原则不止适用于时钟——引脚定义、缓冲区大小、版本号，全都适用。
