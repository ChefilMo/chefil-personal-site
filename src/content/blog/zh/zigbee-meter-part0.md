## 一、为什么要做电表？

做这个项目之前，我先问自己一个问题：**市面上几十块钱的智能插座遍地都是，为什么要亲手做一个三相电表？**

答案有三个：

1. **智能插座是"单相玩具"，三相才是"工业现实"**。家庭入户是单相 220V，但商铺、厂房、出租屋总表几乎都是三相四线制。三相意味着三路电压、三路电流、三路功率、正反两个方向的电量——数据量直接翻了一个数量级。
2. **我想搞懂"计量"这件事**。电压电流可以用 ADC 采，但"电能"是功率对时间的积分，芯片怎么做？校准怎么做？掉电了电量怎么不丢？这些问题的答案，看十篇公众号不如自己写一遍代码。
3. **Zigbee 是个不错的技术洼地**。Wi-Fi 设备教程满地都是，但 Zigbee——这个藏在智能家居网关背后的协议栈（端点、簇、ZCL、配网、OTA），中文世界的动手教程其实很少。

于是就有了这个项目：一个挂在三相回路上的 **Zigbee 3.0 Router 智能电表**，能把每相的电压/电流/功率/功率因数/正反向电量实时上报到涂鸦云，本地有一块段码屏轮显，支持功率超限自动跳闸（继电器断开）、远程 OTA 升级。

最终形态：

- 模组：涂鸦 ZT3L（Telink TLSR8258 芯片，Zigbee 3.0 Router）
- 计量：HLW8112（SPI 接口，负责 A、B 两通道）+ HLW8110（UART 接口，负责 C 通道）
- 显示：VK1621 驱动的段码 LCD，3 位数字 × 2 行 + 图标
- 交互：1 个按键（短按翻页 / 双击自检 / 三击全笔画 / 长按 5 秒配网）+ 1 个 LED
- 执行：1 路继电器（PC0），功率超限自动断开
- 测温：NTC 热敏电阻（ADC）

## 二、技术选型的心路

### 2.1 为什么选 Zigbee 而不是 Wi-Fi？

| 维度 | Zigbee | Wi-Fi |
|------|--------|-------|
| 组网 | 网状网络，设备可互为路由 | 星型，全部依赖路由器 |
| 待机功耗 | mA 级（Router）/ μA 级（休眠端） |  tens of mA |
| 网络拥堵 | 2.4G 16 信道独立，家居场景干净 | 和路由器抢空气 |
| 生态 | 涂鸦网关一键配网 | 配网成功率常年被吐槽 |

电表是**常供电**设备，功耗不是首要矛盾，但电表往往安装在配电箱深处——Wi-Fi 信号穿两堵墙就悬了，而 Zigbee 的网状组网天然适合这种场景（Router 设备还能帮别的设备中继）。

代价是：Zigbee 的开发门槛显著更高。你要理解 **端点（Endpoint）、簇（Cluster）、属性（Attribute）、ZCL 命令** 这套模型，还要有一个支持 Zigbee 的网关。这正是本系列要花前两篇讲清楚的东西。

### 2.2 为什么选 TLSR8258 / ZT3L？

Telink 的 TLSR8258 是一颗很有意思的芯片：BLE 5.0 和 IEEE 802.15.4（Zigbee 的物理层）双模 SoC，Cortex-M0? 不，是 Telink 自研的 32 位 RISC 核（TC32 指令集），512K Flash + 64K SRAM，跑 Zigbee 协议栈绰绰有余，成本又比 EFR32 低一截。涂鸦把 8258 做成了 ZT3L 模组并接入了 TuyaOS 生态，开发资料、网关兼容性都有保障。

工具链是内置在开发包里的 **TC32 GCC 交叉编译器**（`tc32-elf-gcc`），不需要自己装任何东西——这一点在第 01 篇细讲。

### 2.3 为什么计量用"两颗芯片"这种奇怪方案？

这是本项目最有意思的硬件决策。三相要测 3 路电流 +（至少）1 路电压，常见的方案有：

- **三颗单相计量芯片**：成本 ×3，占板面积大；
- **一颗专用三相计量芯片**（如 ATT7022/HLW8032 多通道版）：好是好，但选型时要么缺货要么封装难焊；
- **HLW8112 + HLW8110 混搭**（本方案）：HLW8112 是一颗双通道计量芯片，**SPI 接口**，一次初始化就能并行计量 A、B 两路；HLW8110 是它的单通道姊妹型号，**UART 接口**，负责 C 路。

这个方案把"SPI 同步读"和"UART 异步读"两种完全不同的驱动模型塞进了同一个项目——前者简单直接，后者引出了本项目最难的一个 bug（第 07 篇的主角）。而且 HLW8112 的两个物理通道和 A/B 相之间还存在**硬件布线交叉**（通道 A 实际接的是 B 相端子），软件里要做交叉映射——第 06 篇会专门讲这个"伏笔"。

### 2.4 为什么用涂鸦私有簇 0xEF00，而不是标准 ZCL？

Zigbee 联盟定义了标准的计量簇（0x0702 Simple Metering），理论上是正道。但涂鸦生态的现实是：App 面板、云端规则、网关的 DP 物模型，全都围绕 **Tuya 私有簇 0xEF00** 的 DP 协议构建。用标准簇，你得自己写网关插件；用 0xEF00，在涂鸦 IoT 平台定义好 DP 点，设备一入网 App 面板直接能用。

所以 pragmatic 的选择是：设备类型报 `ZG_DEVICE_ID_SMART_PLUG`、模型 ID 报 `TS0601`（涂鸦生态约定俗成的"透传设备"型号），数据全走 0xEF00。**这本质上是一套运行在 Zigbee 上的自定义应用层协议**，第 05 篇会逐字节拆解它的帧格式。

## 三、系统架构总览

先看软件分层（这是整个系列的地图）：

```
┌──────────────────────────────────────────────────────────┐
│ 应用层                                                      │
│  生命周期回调         四段式 init + 网络状态机 + OTA 回调      │
│  端点/簇注册          Zigbee 设备描述符与注册逻辑              │
│  DP 协议层            DP 帧解析/封装 + 应用层发送队列          │
│  数据模型             集中式电表数据 + 死区上报 + KV 持久化    │
│  计量聚合             三芯片数据聚合 + NV 电量 + 每小时电量    │
│                      + LCD 轮显                              │
│  双击自检             逐相计量自检                             │
├──────────────────────────────────────────────────────────┤
│ 驱动层                                                      │
│  HLW8112 SPI 驱动     A/B 通道计量，同步读取                   │
│  HLW8110 UART 驱动    C 通道计量，异步状态机                   │
│  VK1621 段码屏驱动    段码映射表 + GPIO 模拟时序              │
│  NTC 测温             ADC 采样 + 341 点查表                   │
│  按键驱动             GPIO IRQ + 20ms 扫描状态机             │
│  LED 驱动             模式机（off/on/快闪/慢闪）             │
│  UART 封装            9600 8E1，计量芯片专用                  │
│  GPIO 封装            继电器驱动 + 上电 3 次配网检测           │
├──────────────────────────────────────────────────────────┤
│ TuyaOS SDK（TAL 抽象层 + TKL 内核层 + 预编译 .a 库）          │
└──────────────────────────────────────────────────────────┘
```

硬件资源分配（改代码前务必背下来的一张表）：

| 功能 | 引脚 | 说明 |
|------|------|------|
| 按键 | PB4 | 上拉输入 + 下降沿 IRQ，低电平有效 |
| LED | PB5 | 推挽输出 |
| 继电器 | PC0 | 高电平吸合 |
| SPI→HLW8112 | SDI=PD7, SCLK=PD3, SDO=PD4, CS=PC1 | GPIO 模拟 SPI |
| UART0→HLW8110 | TX/RX | 9600 8E1，**独占** |
| LCD→VK1621 | CS=PC2, WR=PC3, DATA=PD2 | GPIO 模拟时序 |
| NTC | PB6 (ADC ch6) | 3.3V 参考，4 次平均 |
| 调试 log | PC4 | GPIO 模拟 UART，115200（`Tl_printf`） |

> 注意一个关键事实：**UART0 从启动后期就完全交给 HLW8110**，日志走 PC4 的模拟串口。这是 evolved 后的设计——最早版本 log 和计量共用 UART0，带来一场著名的"串口争夺战"（第 07 篇讲）。

## 四、38 个 DP 点：设备的"语言"

涂鸦物模型里，每个数据点叫一个 DP（Data Point）。本项目所有 DP 编号在代码中统一定义为一组宏，共 38 个，分五类：

- **累计电量（14 个）**：总正/反向 + 按端子 3 路正/反向 + 按相 3 路正/反向（DP 1/2、56–61、125–130）
- **实时数据（11 个）**：电压、3 路电流、3 路功率、3 路功率因数、总功率、温度（DP 9、101–110、131）
- **配置（11 个，可写）**：继电器开关、3 路功率阈值、7 项校准值（DP 16、111–113、132–138）
- **报警（3 个）**：3 路功率超限报警（DP 114–116）
- **每小时电量（8 个）**：A/B/C/总 × 正/反向（DP 117–124）

云端物模型里定义的 DP 和代码中的宏是一一对应的。写固件之前先建云产品、定义 DP——这个流程在第 05 篇展开。
