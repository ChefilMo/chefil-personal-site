> 交互还差最后一块：声音。按键按了要确认、告警触发要提醒、五连击 OTA 要提示——都靠一颗蜂鸣器。
> 本篇的技术核心不是"让它响"，而是**"响着的时候，主循环一分钟都不能停"**。这是嵌入式里又一个反复出现的主题：时间片调度，谁都不能霸占 CPU。

---

## 一、本篇目标与效果

**目标**：TIM 输出 PWM 驱动无源蜂鸣器，实现非阻塞的蜂鸣调度——

1. 短鸣 100 ms（事件提示音）；
2. 长鸣 2 秒（模拟"五连击 OTA 确认"提示，第 16 篇接真）；
3. 滴滴滴 10 秒（告警：响 500 ms / 停 500 ms，循环 10 秒）；
4. 蜂鸣期间挂出"忙"标志，第 7 篇的 UART 窗口顺延正式兑现。

**做完你会懂**：有源/无源蜂鸣器的本质区别、PWM 频率和音调的关系、以及非阻塞任务的时间片写法。

## 二、原理 10 分钟

### 2.1 有源 vs 无源：一字之差，电路完全不同

第 0 篇买装备时特意叮嘱"买无源"——现在讲为什么：

- **有源蜂鸣器**：内部自带振荡电路，给直流电就按固定频率响。控制最简单（GPIO 高低电平），但**音调不可控**，而且待机电流不小；
- **无源蜂鸣器**：本质是一个电磁振膜+线圈，**给什么频率的交流就响什么音调**。控制它需要输出方波——但换来两个产品级好处：音调可选（选一个不刺耳、响度功耗平衡的频段）、以及**省电**（静态时零电流，响的时候才耗电）。

产品的蜂鸣器经 8050 三极管驱动（IO 电流不够直接推线圈），高电平导通。

### 2.2 PWM：定时器替你翻 GPIO

让 GPIO 软件翻转产生 2700 Hz 方波？可以，但 CPU 每 185 µs 就要被叫醒翻一次电平，蠢且耗。TIM 的 PWM 模式就是为这个发明的：**配置一次，硬件自动输出方波**，CPU 零负担。

频率公式：

```
输出频率 = 定时器时钟 / ((PSC + 1) × (ARR + 1))
```

72 MHz 定时器时钟，要 2700 Hz：`PSC = 71`（先 1 MHz），`ARR = 370`（1 MHz ÷ 370 ≈ 2704 Hz，够了）。占空比由比较寄存器 CCR 控制：`CCR = 185` 约 50%；`CCR = 259` 约 70%。

### 2.3 2700 Hz 的来历：一场人体实验

2700 不是计算出来的，是**试出来的**。产品的真实迭代记录：最初 2700 Hz → 想更响亮试了 4000 Hz → **太刺耳，全组否决，改回 2700**；占空比从 50% 调到 70% 补响度。蜂鸣器的"声学参数"没有理论最优解，只有"目标用户群在真实环境里不烦"的实测解——这类参数表上应该永远标注一行小字："人体实测，勿纯理论推导"。

### 2.4 非阻塞：响 10 秒 ≠ 占机 10 秒

最朴素的蜂鸣写法：

```c
void beep_10s_naive(void)
{
    for (int i = 0; i < 10; i++) {   // 响500ms停500ms × 10
        pwm_on();  delay_ms(500);
        pwm_off(); delay_ms(500);
    }
}
```

这在学习板上能响，但在产品里是**灾难**：这 10 秒里主循环停摆——串口协议栈断粮（第 9 篇的 `wifi_uart_service` 没人喂）、看门狗没人喂（第 6 篇：好在这条狗会自动咬复位，算救命）、UART 窗口逻辑全乱。**一个功能模块，没有权力冻结整个系统**。

非阻塞写法是把这个循环"拍扁"成状态机，摊到 10 ms tick 上：

```
蜂鸣任务状态机：
  IDLE ──beep_start(时长,模式)──▶ ON（倒计时 500ms，PWM 开）
                                  │时间到
                                  ▼
                                OFF（倒计时 500ms，PWM 关）
                                  │时间到        │总时长到
                                  ▼              ▼
                            （回 ON，循环）   IDLE（PWM 关）
```

主循环每 10 ms 调一次 `beep_task()`，蜂鸣任务自己管理自己的节奏——和第 7 篇主状态机、第 11 篇缓存状态机是**同一种思想**：**所有长过程都拆成状态机，所有等待都变倒计时**。这个句式在本系列已经第三次出现了，它值得你抄进笔记本的扉页。

## 三、动手写代码

### 第一步：TIM PWM 配置（TIM3 CH1，PA6）

```c
static void beep_pwm_init(void)
{
    RCC->APB1ENR |= RCC_APB1ENR_TIM3EN;
    RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;

    GPIOA->CRL &= ~(0xF << 24);       // PA6 复用推挽 50MHz（AFIO 默认映射 TIM3_CH1）
    GPIOA->CRL |=  (0xB << 24);

    TIM3->PSC = 72 - 1;               // 72MHz → 1MHz
    TIM3->ARR = 370;                  // 1MHz / 370 ≈ 2704Hz
    TIM3->CCR1 = 259;                 // 占空比 70%
    TIM3->CCMR1 = (6 << 4)            // PWM 模式 1
                | TIM_CCMR1_OC1PE;
    TIM3->CCER = TIM_CCER_CC1E;       // CH1 输出使能
    TIM3->CR1 = TIM_CR1_ARPE;
    /* 注意：这里不开 TIM_CR1_CEN，由 beep 任务按需要启动 */
}

static void pwm_on(void)  { TIM3->CR1 |= TIM_CR1_CEN; }
static void pwm_off(void) { TIM3->CR1 &= ~TIM_CR1_CEN; TIM3->CNT = 0; GPIOA->BSRR = GPIO_BSRR_BR6; }
```

### 第二步：非阻塞蜂鸣任务

```c
typedef enum { BP_IDLE = 0, BP_ON, BP_OFF } bp_state_t;

static bp_state_t s_bp = BP_IDLE;
static uint16_t s_bp_tick = 0;        // 当前相位剩余
static uint16_t s_bp_total = 0;       // 总时长剩余
static uint16_t s_bp_on_ms = 500;     // 响/停节奏
static uint16_t s_bp_off_ms = 500;

bool beep_is_busy(void) { return s_bp != BP_IDLE; }

void beep_start(uint16_t total_ms, uint16_t on_ms, uint16_t off_ms)
{
    s_bp_total = total_ms; s_bp_on_ms = on_ms; s_bp_off_ms = off_ms;
    s_bp = BP_ON; s_bp_tick = on_ms;
    pwm_on();
}

void beep_task_10ms(void)             // 主循环每 10ms 调用
{
    if (s_bp == BP_IDLE) return;
    if (s_bp_total <= 10) {           // 总时长到：收工
        s_bp = BP_IDLE; pwm_off(); return;
    }
    s_bp_total -= 10;

    if (--s_bp_tick > 0) return;      // 当前相位没到点
    if (s_bp == BP_ON) { s_bp = BP_OFF; s_bp_tick = s_bp_off_ms; pwm_off(); }
    else               { s_bp = BP_ON;  s_bp_tick = s_bp_on_ms;  pwm_on();  }
}
```

三种音效就是三种参数：

```c
beep_start(100,  100,   0);    // 短鸣：100ms 一声
beep_start(2000, 2000,  0);    // 长鸣：连续 2s（OTA 确认）
beep_start(10000, 500, 500);   // 滴滴滴：10s 间歇（告警）
```

### 第三步：挂进主循环（窗口顺延兑现）

```c
/* PROCESS 状态的 tick 里 */
beep_task_10ms();
if (beep_is_busy())                 // 蜂鸣忙 → 第 7 篇的顺延条件
    s_window_tick = 0;

/* SLEEP 状态：进 STOP 前 */
pwm_off();                          // Deepstop 期间必须静音且引脚拉低
```

## 五、原版对照（CIU32F003）

产品的蜂鸣器子系统参数和细节：

1. **PA5 + TIM3 PWM，2700 Hz，占空比 70%**——就是 2.3 节那场人体实验的结论；
2. **音效语义三件套**：五连击 OTA 确认 = 长鸣 2 秒（**长鸣结束后再进 Bootloader**——提示音必须完整，不能响一半就复位）；温/湿度告警 = 滴滴滴 10 秒（500/500 节奏）；短按提示音 = **已取消**；
3. **静音是产品定义**。告警音效受"告警静音"DP 控制（第 11 章词汇表的 mute，**出厂默认静音**）——用户对"半夜突然滴滴滴"的容忍度是负数，声音必须是 opt-in；
4. **告警期间是醒着的**。滴滴滴的 10 秒里设备不进 Deepstop：PWM 时钟停摆、引脚状态不可控、提示音会断——所以蜂鸣忙加入顺延条件（第 7 章）和睡眠守卫；
5. **Deepstop 期间 PA5 必须为低**。进 STOP 前 `pwm_off()` 且引脚主动拉低，防止三极管半导不通不透地漏电（第 5 章"入睡前检查清单"又添一条）。

## 六、彩蛋一：短按提示音的"生死"

学习版的验收清单里让你实现了按键短鸣——然后告诉你产品把它砍了。这不是功能做不出来，是**三个产品级理由的合谋**：

1. **省电**：每次短鸣 100 ms 的电流对电池账本是纯支出，而它服务的是"按键有反馈"这种可替代体验（LCD 刷新本身就是反馈）；
2. **场景干扰**：温湿度计常见于卧室，夜间任何提示音都是负分（静音 DP 默认静音，同理）；
3. **产线噪音**：工厂里几百台设备同时测试，每台都"滴"就没人听得见了。

这个取舍值得记下来：**功能的有无不取决于"能不能做"，而取决于"做了以后所有场景的总收益"**。学习阶段什么都实现，产品阶段到处砍功能——这不是退步，是两种不同的工种。

## 七、彩蛋二：阻塞式蜂鸣的"死因解剖"

真实的排查现场还原：某次联调告警功能，测试同事报告"触发告警后，设备 10 秒内 App 无响应，之后一切正常"。

看代码：`beep_alarm()` 里藏着第 2.4 节那个朴素循环。10 秒里 `wifi_uart_service()` 断粮——模组发来的心跳无人应答，按协议约定模组判定"MCU 死了"，断开重连；10 秒蜂鸣结束，主循环恢复，一切"正常"。

这个 bug 的经典之处在于它的**表象完全指向错误的方向**："App 无响应"第一反应是网络问题、云端问题、Wi-Fi 模组问题——谁会怀疑一颗蜂鸣器？而它不过是"一个模块用 `delay_ms` 冻结了系统"的最普通形态。**排查任何'周期性失联'，先列出失联窗口内所有执行了 delay 的代码**——这是本案留下的一条可以直接用的经验。
