> 产品有脸（LCD）了，还缺一只手：用户怎么跟它交互？本产品的答案是一颗按键——全部交互压缩到一颗 PB2 上：短按看数据、长按配网、连击五下触发 OTA。
> 一颗按键做出三种手势，加一条隐藏需求：**设备睡着的时候按，它得醒**。这就是本篇的两条主线。

---

## 一、本篇目标与效果

**目标**：实现完整的按键子系统——

1. 10 ms 轮询消抖，稳定识别按下/松开；
2. 手势识别：单击、双击、多击（连击计数）、长按（2 秒，学习版阈值）；
3. EXTI 双边沿唤醒：STOP 睡眠中按下按键，设备醒来并报告"被按键叫醒"；
4. 挂进第 7 篇状态机：单击 = 强制上报，长按 = 打印"进入配网（占位，第 17 篇接真）"。

**做完你会懂**：机械抖动是什么、为什么消抖必须用轮询而不是中断、多击手势的计时窗口怎么设计、以及"睡眠唤醒"和"醒着手势"为什么是两条并行的路线。

## 二、原理 10 分钟

### 2.1 抖动：一颗按键的内心世界

机械按键不是干净的开关。触点闭合的瞬间会弹跳几毫秒到二十毫秒，波形像这样：

```
理想：  ──────┐        ┌──────────────
              └────────┘
实际：  ──────┐ ┌┐ ┌─┐   ┌──┐ ┌────────
              └─┘└─┘ └──┘  └──┘
              ←抖动区→
```

如果每个边沿都当真，一次按下会被读成"按了 5 次"。消抖的思路是**用时间过滤**：只有电平**稳定**保持若干毫秒，才算一次真实的按下。

### 2.2 为什么消抖靠轮询，不靠中断

直觉上"按键用中断"很自然，但抖动区里电平反复横跳，中断会被打爆——20 ms 的抖动可能触发十几次中断，每次进中断都不知道该不该信。

所以产品级方案永远是**轮询 + 定时采样**：主循环的 10 ms tick（第 7 篇 PROCESS 状态的节拍）里读一次按键电平，用一个小状态机做"稳定判定"：

```
IDLE ──读到按下──▶ DEBOUNCE（再确认2次）──确认──▶ PRESSED
  ▲                                               │      │
  │                                          持续按住   读到松开
  │                                               │      │
  │                                          （计时，    ▼
  │                                           等长按） RELEASE_DEBOUNCE ──确认──▶ 计数/派发手势
  └──────────────────────────────────────────────────────────────┘
```

### 2.3 多击与长按：两个计时器的事

手势识别的全部秘密就是**两个计时量**：

- **按住时长** `hold_ms`：按下期间每 10 ms 累加。超过长按阈值（产品 5 秒）→ 派发长按事件（只派一次，期间不再算单击）；
- **连击窗口** `multi_click_ms`：松开后启动一个倒计时（产品 600 ms）。窗口内再次按下 → 计数 +1、窗口重置；窗口耗尽 → 按计数派发：1=单击、2=双击、5=五连击……

注意一个设计约束：**长按派发时机**。不能在"按住满 5 秒"的当刻立即派发——如果用户在 5.5 秒时松手，5 秒处派发的长按和松开处的单击会打架。产品的做法是长按在**松开时**结算：按住期间只置标志，松开瞬间看标志——"长按标志在、时长够"→ 派发长按并吞掉本次计数；否则按计数派多单击。简单且无歧义。

### 2.4 两条并行路线：醒着轮询，睡着中断

本篇开头埋的"两种路线"现在展开：

- **设备醒着**：走 2.2 的 10 ms 轮询状态机，识别完整手势；
- **设备睡着（STOP）**：轮询停摆，此时靠 **EXTI 双边沿中断**（第 5 篇的能力）把设备叫醒，中断里只干一件事——**锁存一个"按键唤醒"标志**。

 waking 后的流程有个微妙处：按键把人叫醒的时候，手指多半还按着呢，醒来的轮询状态机从"按下稳定"状态接着跑，手势照样能识别完整——**中断负责醒，轮询负责懂**，分工干净。

## 三、动手写代码

### 第一步：消抖 + 手势状态机（10 ms tick）

```c
#define BTN_LONG_PRESS_MS     2000     // 学习版长按 2s（产品 5s）
#define BTN_MULTI_WINDOW_MS    600
#define DEBOUNCE_CNT             2     // 连续 2 次采样确认（20ms 抗抖）

static const uint32_t BTN_PIN = 1 << 0;    // PA0，低电平按下

typedef enum { EV_NONE, EV_SINGLE, EV_MULTI, EV_LONG } btn_event_t;

static btn_event_t button_task_10ms(void)      // 挂在主循环 tick 上
{
    static uint8_t  state = 0, cnt = 0;
    static uint16_t hold_ms = 0, window_ms = 0, clicks = 0;
    static bool     long_flag = false;

    bool pressed = ((GPIOA->IDR & BTN_PIN) == 0);

    btn_event_t ev = EV_NONE;

    switch (state) {
    case 0:                                     // IDLE
        if (pressed) { cnt = 0; state = 1; }
        else if (clicks > 0 && ++window_ms >= BTN_MULTI_WINDOW_MS) {
            ev = (clicks == 1) ? EV_SINGLE : EV_MULTI;   // 窗口耗尽，结算手势
            clicks = 0;
        }
        break;
    case 1:                                     // DEBOUNCE 按下确认
        if (pressed && ++cnt >= DEBOUNCE_CNT) {
            state = 2; hold_ms = 0; long_flag = false;
        } else if (!pressed) state = 0;
        break;
    case 2:                                     // PRESSED 按住中
        if (++hold_ms >= BTN_LONG_PRESS_MS) long_flag = true;
        if (!pressed) { cnt = 0; state = 3; }
        break;
    case 3:                                     // RELEASE 松开确认
        if (!pressed && ++cnt >= DEBOUNCE_CNT) {
            if (long_flag) { ev = EV_LONG; clicks = 0; }
            else { clicks++; window_ms = 0; }    // 计入一次点击，等连击窗口
            state = 0;
        } else if (pressed) state = 2;
        break;
    }
    return ev;
}
```

### 第二步：EXTI 唤醒 + 锁存

```c
volatile bool g_wakeup_by_button = false;

void EXTI0_IRQHandler(void)             // 双边沿，PA0
{
    EXTI->PR = EXTI_PR_PR0;             // 清标志
    g_wakeup_by_button = true;          // 只锁存，别的不干（第 5 篇的原则）
}
```

### 第三步：挂进状态机

```c
/* PROCESS 状态 tick 里 */
switch (button_task_10ms()) {
case EV_SINGLE:
    s_force_report = true;              // 单击 = 强制上报（第 7 篇的判定清单①）
    uart_puts("[btn] single -> force report\r\n");
    break;
case EV_MULTI:
    uart_puts("[btn] multi-click xN\r\n");
    break;
case EV_LONG:
    uart_puts("[btn] LONG -> enter pairing (stub)\r\n");   // 第 17 篇接真
    break;
}

/* WAKEUP 状态开头 */
if (g_wakeup_by_button) {
    g_wakeup_by_button = false;
    uart_puts("[wakeup] by button\r\n");
    s_force_report = true;              // 睡梦中被按醒 = 用户等着看数据，立即上报
}
```

## 四、烧录与验收

- [ ] 单击：串口 `[btn] single -> force report`，且下一周期进入上报窗口（第 7 篇联动）；
- [ ] 快速双击、三连击：打印 multi-click，**节奏测试**——超过 600 ms 的两次单击应算两次单击而非双击；
- [ ] 按住 2 秒以上再松：打印 LONG；按住不动期间不重复触发；
- [ ] 五连击（600 ms 内五下）：连击计数到 5（产品里这是 OTA 触发，第 16 篇接真）；
- [ ] STOP 睡眠中按下：设备醒来、先打印 `[wakeup] by button`、随后正常跑手势识别——**醒和懂各司其职**；
- [ ] （手感实验）把 DEBOUNCE_CNT 改成 0（不消抖），快速按一下看串口事件乱飞——抖动第一次变得可见。

## 五、原版对照（CIU32F003）

产品的按键子系统是本篇的完整版，参数和语义都更"产品"：

1. **PB2 低电平有效，外部上拉**——省一个内部上拉电阻的 BOM 钱，代价是 IO 配置要和硬件确认清楚；
2. **长按 5 秒 = 重置 Wi-Fi 进配网**。阈值从 3 秒改成 5 秒，原因是 3 秒太容易误触（设备握在手里就被重置了），5 秒是"有意为之"的下限。改完阈值还要配套：重置后设备保持唤醒等配网，最长 3 分钟，连云后恢复低功耗周期——**手势的终点是一整条业务流程**；
3. **五连击 600 ms 窗口 = OTA 触发**。窗口从 300 ms 加宽到 600 ms，因为"五下快按"对普通用户是极限操作，300 ms 的节拍要求太高，测试人员都按不出来；
4. **按键忙顺延窗口**。识别到手势后，第 7 章的 UART 窗口计时清零顺延——用户在操作时不许睡；
5. **睡眠按键的锁存细节**。产品上电初始化时会清一次按键唤醒标志，只保留 Deepstop 期间的锁存——防止初始化阶段的按键毛刺被误当作用户唤醒。

## 六、彩蛋：那颗被轮询"漏掉"的按键

事件驱动改造（第 7 篇彩蛋提过：无事时醒来只有 50 ms）之后，出了一个微妙的边缘问题：设备醒着的 50 ms 里，如果用户恰好按下又松开了按键，10 ms 轮询能抓到——但**如果按键动作恰好跨过"入睡"边界**（比如在进入 STOP 的前几毫秒按下），轮询状态机还没来得及确认，设备就睡了。

表现为：用户按了一下，设备没醒（因为 EXTI 唤醒配的是"边沿"，而按下产生的边沿恰好落在 GPIO 还没配好 EXTI 的窗口里）——极小概率，但测试足够久一定能遇到。

产品的兜底设计很优雅：**EXTI 的锁存标志在醒来后不完全清除，而是保留一份给 WAKEUP 状态检查**——哪怕轮询没识别出手势，只要 EXTI 锁存显示"睡着期间有按键边沿"，就视同按键唤醒，启动上报周期。这是"中断负责醒"路线的延伸：**轮询可能漏，中断锁存不撒谎**。

这个案例的普适教训：**凡是两条路线并行（轮询/中断、软件/硬件），就要有"仲裁机制"处理交接窗口**——两条路线都声称自己可靠时，交接缝里的丢包才是真相。
